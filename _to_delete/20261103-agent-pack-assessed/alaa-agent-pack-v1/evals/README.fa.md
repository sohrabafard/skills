# ارزیابی واقعی انتخاب مدل

۳۶ مورد در `cases.json` طرح آزمون‌اند، نه بنچمارک اجراشده. چون مخزن و fixture واقعی
در این گفتگو در اختیار نیست، هیچ درصد قبولی یا برتری زبانی ادعا نمی‌شود.

## طراحی آزمایش

- پایلوت: ۱۲ مورد منتخب از Python/PHP/JS/UI و داده، هر چهار مدل، سه اجرای مستقل؛
  ۱۴۴ اجرا. پس از تأیید هزینه/زمان، کل ۳۶ مورد × ۴ مدل × ۳ تکرار = ۴۳۲ اجرا.
- این تعداد تضمین معنی‌داری آماری نیست. نتایج را به تفکیک خانواده کار و شدت ریسک
  گزارش کنید؛ با نمونه کم، فاصله عدم‌قطعیت وسیع است.
- هر اجرا از وضعیت یکسان و تمیز پروژه آغاز شود؛ harness، ابزار، prompt، نسخه،
  بودجه wall time و سیاست retry یکسان باشد. با effort=medium شروع کنید، سپس
  برای taskهای دشوار high را جدا بسنجید. معنای هزینه effort میان مدل‌ها برابر نیست.
- ترتیب اجرا را تصادفی کنید؛ اثر cache، شبکه و بار ماشین را ثبت کنید. reviewer
  انسانی از نام مدل بی‌خبر باشد. راه‌حل و hidden tests به candidate نشت نکند.
- success@1 را از موفقیت پس از اصلاح جدا کنید؛ هزینه تمام تلاش‌ها و review و
  دخالت انسانی را در cost per accepted task لحاظ کنید.
- نتیجه گم‌شده یا timeout را حذف نکنید؛ آن را failure ثبت کنید. مقایسه task setهای
  متفاوت، معتبر نیست. نمونه ارزیابی را با اطلاعات محرمانه production پر نکنید.

## گیت و امتیاز

ابتدا گیت‌های مستقل: معیارهای پذیرش، عدم شکست امنیت/تمامیت مهم، صداقت گزارش
تست و رعایت دامنه. خطای مهم امنیتی با prose خوب جبران نمی‌شود.

پس از گیت، وزن پیشنهادی برای قضاوت کور: صحت ۴۰٪، قرارداد/معماری ۲۰٪، کیفیت
شواهد و تست ۲۰٪، نگهداشت‌پذیری ۱۰٪، کنترل دامنه و صداقت ۱۰٪. این وزن‌ها انتخاب
طراحی‌اند، نه معیار رسمی OpenAI. طول پاسخ یا اعتمادبه‌نفس مدل را امتیاز ندهید.

برای review: precision/recall یافته‌ها و false positive مهم‌اند. برای research:
پشتیبانی واقعی منبع از ادعا. برای performance: بهبود اندازه‌گیری‌شده تحت شرایط ثابت.
برای documentation: درستی و پوشش رفتار و کیفیت نگارش. همه را در یک میانگین خام
ادغام نکنید و تفاوت مدل‌ها را بدون داده قطعی نخوانید.

## قالب نتایج

هر خط JSONL یک اجرای مستقل است:

```json
{"case_id":"PY01","model":"gpt-6.1-terra","effort":"medium","run":1,"attempts":1,"accepted":true,"first_attempt_accepted":true,"critical_failure":false,"cost_usd":0.15,"wall_seconds":85,"human_minutes":2,"language_or_domain":"python","evidence":"path/to/log-and-diff","synthetic":false}
```

عددهای بالا فقط مثال قالب‌اند و اندازه‌گیری واقعی نیستند. `cost_usd` شامل هزینه
واقعی همه تلاش‌ها، ابزار و review است؛ تبدیل زمان انسان به پول را در فیلد جدا یا
تحلیل تکمیلی نگه دارید. اگر هزینه معلوم نیست null بگذارید؛ اسکریپت هزینه کامل
گزارش نمی‌کند. wall time شامل retry باشد. تلاش دوم به‌عنوان run مستقل ثبت نشود.

`summarize_eval.py` نرخ قبولی، success@1، فاصله Wilson تقریبی، زمان و هزینه
ثبت‌شده را خلاصه می‌کند. فاصله Wilson فرض استقلال دارد؛ تکرار یک case مستقل از
caseهای دیگر نیست و برای تصمیم نهایی از تحلیل paired/cluster بر اساس case بهره
بگیرید. این ابزار مدل را اجرا نمی‌کند و به سرویس API وصل نمی‌شود.

Terra را ابتدا فقط در خانواده‌هایی ارتقا دهید که گیت‌ها را می‌گذرانند و هزینه/زمان
کل مناسب دارند. نیاز بیشتر به اصلاح یا review می‌تواند مزیت قیمت توکن را خنثی کند.
