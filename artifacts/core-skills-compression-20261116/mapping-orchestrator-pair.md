# Mapping orchestrator pair

Read-only mapping report, 2026-11-16. Dated evidence: verify a line number before relying on it.

The mapping is complete; the main cost driver is generated contract text, not hand-written prose. In cc, 13 of the 33 agent files are generated wrappers that each carry a whole contract asset verbatim. In codex it is 18 of 37 agent files. On top of that, about 210 to 290 words of required boilerplate repeat in every agent file. Word counts come from `wc -w`. Nothing was edited, and no checker or render script was run.

## 1. Generation

**Script:** `scripts/render_agents.py --write | --check` in each pack. Exit 0 is clean, 1 is drift, 2 is error. The engine is `alaa-prompting-guide/scripts/profile_projection.py` (`expected_profiles` at lines 67–102, `neutral_agent_text` at 105–146).

**What it does**
- For every profile listed in `assets/profile-wrappers.json`, it writes `agents/<name>.md` (cc) or `.toml` (codex). The file is the wrapper frontmatter (`description`, `disallowedTools`/`tools`, `skills`, `color` in cc; `description`, `sandbox_mode` in codex), then a header line `# Generated by scripts/render_agents.py; edit <contract>.`, then the contract file verbatim.
- For the 4 stack profiles it inserts the one-line `binding` immediately before `\nEngineering baseline:` (profile_projection.py:89–96).
- Codex only: `alaa-reviewer.toml` and `alaa-reviewer-deep.toml` are generated from `assets/reviewer-contract.md` (codex render_agents.py:42–80). In cc, `alaa-reviewer.md` is hand-written.
- Every other agent file is **both source and output**. Render only strips `model`/`effort` pins from it.
- `assets/manifest.json` is generated (pack name, `VERSION` contents, sha256 of each agent).
