# Ownership boundary — what this skill does not own

Read this before writing any rule about timeouts, retries, cache key design, log or metric names,
test layering, code shape, or a value that varies by environment. Where a row names another owner,
point at it and write nothing of your own on that ground.

The ten-criterion quality bar itself is owned by `alaa-project-constitution
references/quality-bar.md` and is never restated here. Model and effort selection belong solely to
`/alaa-prompting-guide` (`$alaa-prompting-guide`) `references/50-effort-and-thinking.md`; this skill
names no model. Never edit anything under `vendor/` — upstream git subtrees, re-pulled periodically,
so a local edit is overwritten or collides; wrap them from the owning `alaa-*` skill.

| Criterion | Owner, and who wins on conflict | Retained here |
| --- | --- | --- |
| **Correctness and testability** | `/alaa-testing-strategy` (`$alaa-testing-strategy`). Pest syntax and runner flags: upstream `pest-testing/SKILL.md`, not owned by this repository | the Octane leak regression test and its executable mechanic, because no other skill owns a framework construct |
| **Failure behaviour** | doctrine `/alaa-reliability-sla` (`$alaa-reliability-sla`), which states no value; every value `alaa-services-contract references/22-failure-load-and-deprecation-contract.md`; queues, outbox and DLQ `/alaa-async-messaging` (`$alaa-async-messaging`), RabbitMQ consumers `/alaa-laravel-job-rabbitmq` (`$alaa-laravel-job-rabbitmq`) | worker lifecycle, reload drain, in-flight loss, crash and memory-eviction behaviour; that a blocked request worker consumes one unit of the concurrency ceiling |
| **Security** | `/alaa-security-review` (`$alaa-security-review`) for threat classes, review triggers and the fail-closed discriminator; `/alaa-trust-gateway-auth` (`$alaa-trust-gateway-auth`) for trusted headers, JWT verification and tenant derivation; `/openfga` (`$openfga`) for object-level relationship authorization | the cross-request retention invariants, which under a worker *are* the tenant-isolation mechanism, and how an already-derived tenant value is held and reset |
| **Observability** | every field, event, code and metric **name** `/alaa-services-contract` (`$alaa-services-contract`) `references/24-metric-registry.md`; every requirement **level**, gate and reason, including whether profiling may be enabled, `/alaa-observability-soc` (`$alaa-observability-soc`). SOC wins on whether something is required; the contract wins on what it is called | only the signals a long-lived worker uniquely produces, named as signals rather than as fields |
| **Concurrency and load** | shedding and admission doctrine `/alaa-reliability-sla` `references/40-admission-and-shedding.md`, thresholds in `alaa-services-contract references/22-…`; Redis key shape, TTL, invalidation, stampede control, the repository-pattern gate and the Redis-down fallback contract `alaa-data-layer references/50-redis-laravel-octane.md` (`/alaa-data-layer`, `$alaa-data-layer`), which wins on what is cached and how it is keyed | the worker count as the concurrency ceiling, connection lifecycle and the connection-count ceiling, the three cache tiers, lock contention under long-lived workers |
| **Clean code, SOLID, design patterns** | `/alaa-php-clean-code` (`$alaa-php-clean-code`) `references/design-patterns.md` for selection and `references/octane-clean-code.md` for pattern-by-pattern application under a worker, which cites the invariants by name | nothing about code shape; only the invariants those files cite |
| **Algorithms and data structures** | `/alaa-algorithms-data-structures` (`$alaa-algorithms-data-structures`) | one amortisation note: boot cost is amortised across requests, per-request cost is not |
| **Configurability** | `alaa-services-contract references/22-failure-load-and-deprecation-contract.md` for every value that varies by environment or scale; container CPU and memory limits declared per `/alaa-docker-production` (`$alaa-docker-production`) and `/alaa-k8s-helm` (`$alaa-k8s-helm`) | Octane's own knobs — `flush` list, worker and task-worker counts, `max_requests`, driver selection — their boot validation, and how a worker count is derived from a container CPU quota |
| **Speed of development and debuggability** | `/alaa-workflow` (`$alaa-workflow`) for plan files, phasing and resumable state; `/alaa-controlled-ops` (`$alaa-controlled-ops`) for risky operations and proof strength; `/alaa-cc-orchestrator` (`$alaa-codex-orchestrator` in Codex) for lane planning, role prompts and review gates | the named load tool, profiler, RSS sampler and bisect recipes in `references/diagnostic-drills.md` |
| **Documentation** | `/alaa-laravel-architecture` (`$alaa-laravel-architecture`) for layering, DTO boundaries and provider discipline; `/alaa-system-design` (`$alaa-system-design`) for the pre-implementation design pass and the change classes that require one | the operations record for worker runtime: how the service is operated and how it fails |
