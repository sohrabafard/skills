# API Surface

Organised by what you are trying to do. Every entry names the object or function to call; the HAProxy Lua API reference in `references/SOURCES.md` carries the full parameter lists, and it states the legal contexts for each call. Check the context before calling: an API used outside its documented context fails at runtime, not at configuration parse time.

## Registering behaviour

Register configuration-facing converters, fetches, actions, services and filters at load time. Init callbacks, tasks, events and Runtime API commands have their own invocation paths; they are not all `lua.` configuration keywords. Check each pinned API signature/context before use.

| You need | Call | Handler shape |
|---|---|---|
| a value transformed in a sample expression | `core.register_converters(name, func)` | `function(str, [p1 ... p12]) -> sample-compatible value` |
| a value produced from the transaction | `core.register_fetches(name, func)` | `function(txn, [p1 ... p12]) -> sample-compatible value` |
| transaction work or a control-flow decision | `core.register_action(name, actions, func [, nb_args])` | `function(txn, ...) -> act.* or no value` |
| a whole response generated by Lua | `core.register_service(name, mode, func)` | `function(applet)` |
| callbacks over the request and response bodies | `core.register_filter(name, Flt, func)` | a class with filter callbacks |
| work at startup, after configuration parsing | `core.register_init(func)` | `function()` |
| background work concurrent with traffic | `core.register_task(func [, arg1 … arg4])` | `function()` |
| an operator command on the runtime socket | `core.register_cli([path], usage, func)` | `function(applet, …)` |
| reaction to a server or backend event | `core.event_sub(event_types, func)`, `Server.event_sub(sv, …)` | `function(event, data, …)` |

The v3.4.6 registration source accepts twelve optional string arguments for converters and fetches (`ARG12`, `src/hlua.c` lines 10751 and 10837), and configuration arguments arrive as strings even when written as numbers. Return conversion, including booleans, is owned by `references/30-failure-visibility.md`. The API prose inconsistently says five/nine; use the tagged source and a parser probe for this limit. Convert with `tonumber` and reject the result when it is `nil`.

Load-time arguments are separate: `lua-load <file> <arg1> <arg2> …` delivers them to the file body through `local args = table.pack(...)`, with Lua's 1-based indexing.

## Reading and writing the transaction

`TXN` is the object handed to actions and sample fetches.

- **HAProxy variables** — `TXN.set_var(txn, name, value [, ifexist])`, `TXN.get_var(txn, name)`, `TXN.unset_var(txn, name)`. The name follows HAProxy variable syntax, so the scope is part of the name: `txn.` for the transaction, `req.` and `res.` for one direction, `sess.` for the session, `proc.` for the whole process. The reference says of `ifexist`: "If this parameter is set to true the variable will only be set if it was defined elsewhere … It is highly recommended to always set this to true." Pass `true` unless the configuration cannot reference the variable, because a typo in a variable name is otherwise silent.
- **Per-request Lua state** — `TXN.set_priv(txn, data)` and `TXN.get_priv(txn)` share one Lua value between the actions and fetches of a single transaction. These are appropriate places for per-request state; a module-level local is per Lua state and outlives the request.
- **HTTP** — `txn.http` exposes `req_get_headers`, `res_get_headers`, `req_add_header`, `req_set_header`, `req_del_header`, `req_rep_header`, `req_set_method`, `req_set_path`, `req_set_query`, `req_set_uri`, `res_set_status`, and their response counterparts.
- **Ending the transaction** — `TXN.done(txn [, reply])` stops processing, and `TXN.reply([reply])` builds the response object to return.
- **Connection and scheduling attributes** — `TXN.set_mark`, `TXN.set_tos`, `TXN.set_fc_mark`, `TXN.set_fc_tos`, `TXN.set_priority_class`, `TXN.set_priority_offset`, `TXN.set_loglevel`.

## Byte-level access

- **`Channel`** — the raw buffer for TCP and filter work: `data`, `line`, `append`, `prepend`, `insert`, `remove`, `set`, `send`, `forward`, `input`, `output`, `is_full`, `may_recv`, `is_resp`, `get_in_len`, `get_out_len`. `Channel.dup` and `Channel.get` read without and with consuming.
- **`HTTPMessage`** — the filter-side view of one HTTP message, used inside filter callbacks where `Channel` alone is not enough.
- **`AppletHTTP` and `AppletTCP`** — the object passed to a service handler, used to read the request and write the response.

## Reaching outside the process

- **`core.tcp()`** returns a `Socket`. Its calls look blocking and are multiplexed by the scheduler, so they are permitted in runtime contexts, unlike `io.*`.
- **`core.httpclient()`** returns an `HTTPClient` with `get`, `head`, `put`, `post`, and `delete`.

Egress from an edge process is a trust-boundary change; read `references/80-security.md` before adding one.

## Lookups and shared data

- **`Map.new(name, method)`, `Map.lookup(map, str)`, `Map.slookup(map, str)`** read a HAProxy map file from Lua.
- **`core.set_map(name, key, value)`, `core.del_map(name, key)`, `core.add_acl(name, key)`, `core.del_acl(name, key)`, `core.get_patref(name)`** mutate pattern references at runtime.

Map and ACL *file* design belongs to `/alaa-haproxy`; this skill covers only reaching them from Lua.

## Inspecting and steering the load balancer

- **`core.proxies`, `core.frontends`, `core.backends`** enumerate `Proxy` objects; `Proxy.servers`, `Proxy.listeners`, `Proxy.stktable`, `Proxy.get_stats`, `Proxy.pause`, `Proxy.resume`, `Proxy.stop`.
- **`Server`** exposes state and control: `get_stats`, `get_addr`, `set_addr`, `set_weight`, `set_maxconn`, `is_draining`, `is_backup`, `is_dynamic`, `set_drain`, `set_maint`, `set_ready`, `check_enable`, `check_disable`, `agent_enable`, `agent_disable`, `shut_sess`.
- **`core.get_info()`** returns process-level information including uptime, pid, pool usage, and task counts.

Enumeration and `get_*` calls inspect state; setters and administrative methods mutate it. Treat a Lua call that changes server weight, drain, or maintenance as a control-plane action and route the authorisation question to `/alaa-security-review`.

## Time, sleeping, and scheduling

- **`core.now()`** returns a table with `sec` and `usec`, taken from the HAProxy clock. The reference notes the value "is refreshed between each Lua execution or resume, so two consecutive call to the function `now` will probably returns the same result", and documents its contexts as body, init, task, and action.
- **`core.msleep(ms)` and `core.sleep(s)`** are documented for task and action contexts only.
- **`core.yield()`** returns control to the scheduler and is resumed automatically; **`core.wait([ms])`** returns control without automatic rescheduling.
- **`core.http_date`, `core.imf_date`, `core.rfc850_date`, `core.asctime_date`** parse HTTP date formats into epoch integers.

Choose clocks and date formatting by semantics, resolution and enabled libraries; `references/40-time-randomness-identity.md` owns that decision.

## Logging

- **`core.log(level, msg)`** with the levels `core.emerg`, `core.alert`, `core.crit`, `core.err`, `core.warning`, `core.notice`, `core.info`, `core.debug`, and the shorthands `core.Debug`, `core.Info`, `core.Warning`, `core.Alert`. All are legal in body, init, task, action, sample-fetch, and converter contexts.
- **`TXN.log(txn, level, msg)`**, `TXN.deflog`, and the same four shorthands log with the transaction's own logger.

Where the line goes is a configuration property, not a Lua one: `tune.lua.log.loggers` (default `on`) sends Lua output to the proxy's loggers, and `tune.lua.log.stderr` (default `auto`) additionally sends it to stderr when no logger applies. A Lua module that assumes its log line reached the operator has assumed a configuration it did not check.

Log **field and event names** are owned by `/alaa-services-contract`, and whether a given change *requires* telemetry is owned by `/alaa-observability-soc`. This skill states only the mechanism.

## Less common contexts

- **Tasks:** define a bounded unit of work, a scheduler-aware wait, failure/backoff
  policy and stop/drain behavior. A task is per registered Lua state, not a cluster
  singleton. Idempotency or external coordination is required for side effects.
- **CLI handlers:** `register_cli` receives an applet and command arguments. Bound
  input/output and expose only the required Runtime API privilege. Test denied
  access and disconnected clients; do not treat a command's presence as authorization.
- **Filters:** follow the pinned `register_filter` constructor and callback contract,
  use per-stream instances, and preserve callback return/count semantics and message
  framing. Test both directions, empty/end-of-message input and aborted streams.
  Do not call yieldable APIs from a callback unless its specific contract permits it.
- **Events:** keep callbacks bounded and account for subscription lifetime and stale
  server/backend objects. Test deletion/reload behavior before administrative mutation.
- **Services/applets:** read and write through the appropriate HTTP/TCP applet,
  respect backpressure, cap response size, and test disconnects and partial output.

These are routing obligations, not a claim that the bundled converter harness tests
filters, CLI, events or task scheduling. Their deployment-specific behavior needs a
focused harness when used.
