# Test Execution

Read before choosing or running checks, including direct work without an orchestrator. This file owns execution procedure; `SKILL.md` retains scope and result-validity doctrine. Repository validation policy takes precedence. Runtime orchestrators own role authority, observer independence, allocation and phase/review scheduling; this file grants none of those authorities. When orchestration applies, consume the executor/observer mapping in /alaa-codex-orchestrator or /alaa-cc-orchestrator `references/verification-and-gates.md`; direct work preserves its caller's declared authority and required independent observer.

## Prepare the check list

Before execution, record one check list in the existing evidence owner: required gates, exact commands and scoped inputs, cwd, timeout, environment/resource limits, expected cases, declared case dependencies, aggregate-to-child coverage and eligible citations. Record each command's machine-readable reporter when available and retain its output; retain raw exit/output when none exists. Use the existing plan when admitted, otherwise the repository's existing result record; no orchestrator is required. Record the tested content snapshot, relevant untracked inputs and tool versions. Keep check inputs stable during the pass; conflicting changes invalidate affected evidence.

For a new or changed test command, or one with a recorded harness failure, confirm selection before citing its result. When the runner supports list/collect-only mode, run that as a separate selection check before the first execution; otherwise compare the first run's selected cases with the recorded expected cases. Preserve selected and executed counts, case identities and skip/setup reasons, including every covered child of an aggregate. `120-result-classification.md` decides empty, mismatched and selected-but-unexecuted outcomes; a valid collect-only result proves selection alone. Non-test lint/type/build/render commands need no case selection check; record their scope, exit and output.

Inspect aggregate execution: a name proves no coverage. Replace children with an aggregate only when their inputs, environment, flags and required observer match demonstrably; observer authority remains a caller constraint. Count underlying checks once and run uncovered gates separately. Apply the result-validity conditions in `SKILL.md` to final aggregate evidence. Run checker self-tests only when checker logic changes. Reuse builds and reset-safe setup under `90-test-economy.md`.

Before CPU-heavy checks or timing, read `110-execution-resources.md`. Before interpreting any outcome or repairing a failure, read `120-result-classification.md`. Report proof and evidence through `80-evidence-and-reporting.md`.

## Collect, repair, retest

1. **Collect before repair.** Run every required runnable check once, citing eligible evidence. One failure never cancels independent remaining checks. Record each command's exit/result and each unrun check's blocker. A dependent case whose precondition failed is skipped with that precondition named. A fail-fast aggregate proves only executed coverage: use its supported keep-going mode or exact uncovered child commands while preserving failure exits. Stop unsafe or contaminated cases and name them; collection is incomplete while required checks remain unresolved.
2. **Batch repair.** Combine the collection's failures verbatim, classify their causes first, and repair the combined batch within explicit ownership and authority. A clear owner or cheap fix does not bypass collection. Only an obstruction blocking all or most remaining checks permits minimal early repair: record the cause and blocked checks, repair only that obstruction, then resume the full collection, including previously blocked checks. No review or acceptance precedes complete collection and required retests.
3. **Freeze and retest.** After batch repair, rerun the whole recorded check list on the frozen repaired snapshot, including checks previously discharged by citation. Invalidate affected evidence. Extend the list only when the repair changes shared behavior or proves a new reachable surface. New failures follow the same collection barrier within existing retry/stop budgets. Preserve the original failure, repair and retest separately.

Never weaken assertions, suppress findings, lower thresholds, widen tolerances, add assertion retries or alter fixtures to conceal failure. Environment recovery changes require their own authority and evidence. Unresolved required checks block acceptance; continue only safe independent checks. The caller's retry/stop budget still applies and is not reset by collection or a new agent.
