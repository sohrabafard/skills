# Evidence selection and fallback

| Question | Primary owner | Bound |
|---|---|---|
| Code structure, source symbols, callers/callees, usages, impact | Gortex supported graph/semantic operation | Inspect edge provenance, coverage, requested/actual checkout view and freshness |
| Supported edit or refactor | Gortex guarded mutation | `writes.md` owns all mutation gates |
| Laravel/package versioned documentation | Boost documentation capability | First establish versions from the checkout lockfile; official versioned docs if unavailable |
| Laravel registered routes, application metadata, logs, schema | Boost corresponding capability in the intended runtime | WSL PHP CLI is not the running Docker application |
| Database writes, arbitrary runtime evaluation | Separately authorized runtime operation | Never infer read-only authority from the Boost namespace |
| Config, Markdown, literal text, lockfile or generated artifacts | Bounded native read/parser; generator source for generated output | Do not send unsupported formats through a graph |
| Verification | Repository-native test/typecheck/lint/build/schema/generator checks | Same checkout and inputs; never replace with graph confidence |

Boost is absent from non-Laravel routing. Documentation and runtime Boost capabilities fail independently; a docs outage does not justify running arbitrary PHP or querying data. Preserve Hindsight as the established memory owner; do not enable Gortex ingestion, memory writes or a second decision store automatically.

Select one operation for each independently answerable question. Do not repeat source retrieval through a second provider for reassurance. Check tool inventory/schema and current identity without assuming documentation equals installed capability. A partial or empty graph, pagination limit, stale view, heuristic edge, dynamic dispatch gap or degraded LSP cannot prove unused code or complete references.

For a failure, permit at most one cause-specific read-only diagnosis and one materially different retry. Do not restart, reindex, reinstall or change config as an implicit repair. Then use a configured language-native semantic operation for the missing fact, or bounded source/text inspection for a partial claim. Record the failed operation, cause, replacement, lost guarantee and remaining uncertainty. Never cycle back to an exhausted operation or use text matches as a rename proof.

For Laravel Docker facts, record service/container, image/revision, workdir and checkout mapping. For cross-repository questions preserve target repository and target checkout identity on every result; the caller's root is not automatically the target's root. Global skill migration does not override an unchanged project's explicit binding: surface conflicts for the operator to resolve; do not rewrite those bindings automatically.
