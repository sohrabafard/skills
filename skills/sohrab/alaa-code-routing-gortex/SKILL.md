# Alaa Code Routing with Gortex

Name the question and its actual repository/worktree before selecting one evidence owner. Reuse adequate fresh evidence; retrieve only missing facts. Gortex owns supported code structure and semantics, not runtime truth or proof. This skill teaches agents to use an already configured integration; workstation installation and migration belong to operator documentation.

## Decision procedure

1. Bind the session to its actual checkout; inspect returned identity, view freshness and capability before relying on results.
2. Route code questions to Gortex, Laravel documentation/runtime questions to the matching Boost capability, and unsupported artifacts to their native owner. Read `references/routing.md` for selection, finite fallback and uncertainty.
3. Before any supported write, read `references/writes.md`; authorization, guards, receipt recovery and native proof are separate requirements.
4. Read only the conditional reference below that answers the remaining question.

| Condition | Owner |
|---|---|
| Selecting a language provider, root, budget or diagnosing degradation | `references/lsp.md` |
| Using Vue SFCs, TypeScript companions, virtual positions or assessing adapter work | `references/vue.md` |
| Granting tools to a read-only or implementation role | `references/agent-scoping.md` |

## Authority and stopping

Tool availability grants no new authority. Reads, writes, runtime execution, data changes, installation and index lifecycle have separate permission boundaries. Do not install software, edit integrations, start services or ingest memory merely because this skill is active. Gortex graph scope does not sandbox path tools per session.

Success means the named question is answered with attributable evidence and applicable native checks pass. Stop a dependent operation on wrong checkout/view, unsupported safe mutation, unresolved timeout or missing authority; continue unrelated safe work. Report partial graph/LSP coverage explicitly, never as absence.

## When NOT to use

- A precise native owner already answers the question without a routing decision.
- Implementing domain architecture, authoring unrelated documentation or managing task state.
- Treating graph output as test, typecheck, build or deployed-runtime proof.

## Report

State owner, repository/worktree/view, freshness and capability, evidence limits, fallback used, mutation receipt and disk/graph outcomes when applicable, and observed native checks. Distinguish advertised capabilities from observed behavior.
