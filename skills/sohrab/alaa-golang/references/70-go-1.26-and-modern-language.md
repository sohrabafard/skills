# Go 1.26 and Modern Language Baseline

Use this file to write current, idiomatic Go and to force adoption of Go 1.26 features where the repo supports them.
Every fact here was verified against the official release notes (`https://tip.golang.org/doc/go1.26`,
`https://go.dev/doc/go1.26`) and the language spec (`https://go.dev/ref/spec#Allocation`). Re-verify a version-sensitive
claim from `SOURCES.md` before relying on it, and always match — never regress — the repo's `go.mod` `go` directive.

## Version discipline (read first)

- A feature gated on Go 1.26 requires the module's `go` directive to be `>= 1.26`. Do not use `new(expr)` or
  self-referential generics in a module pinned lower; older toolchains reject them.
- `go mod init` under a 1.26 toolchain now writes `go 1.25.0` (one minor below the toolchain), not `go 1.26`. A fresh
  service is compatible with the two currently-supported releases by default. Bump deliberately with
  `go get go@1.26.0` only when the code actually needs a 1.26-only feature, and record why.
- Two escape-hatch mechanisms differ and must not be confused: **`GOEXPERIMENT=...` is set at build time** (compiler /
  runtime experiments and their opt-outs); **`GODEBUG=...` is a runtime setting** (compatibility toggles). Getting this
  wrong produces a flag that silently does nothing.

## Language & spec changes

- **`new` accepts an expression.** `new(x)` now allocates a variable of the type of `x`, initialized to the value of
  `x`, and returns its address (an untyped constant is first converted to its default type). Example:
  `new(int64(300))` returns `*int64` pointing to 300. Use it to build optional/pointer fields for JSON, protobuf, and
  API DTOs — it replaces the `x := v; p := &x` two-liner and hand-rolled `func ptr[T any](v T) *T { return &v }` /
  `lo.ToPtr` helpers, and removes the classic loop-variable-address aliasing bug. `new(T)` for a type is unchanged.
- **Self-referential generic constraints.** The restriction that a generic type may not refer to itself in its own type
  parameter list is lifted: `type Adder[A Adder[A]] interface { Add(A) A }` now compiles. Use it for F-bounded /
  CRTP-style constraints (self-typed builders, fluent APIs, numeric/monoid interfaces whose method returns the concrete
  type). Keep it readable; prefer a plain interface in repository/service layers where generics add no value.

## Toolchain & `go` command

- **`go fix` is the home of modernizers.** It was rewritten on the same `go/analysis` framework as `go vet`, ships
  dozens of behavior-preserving fixers, and is the push-button way to move a codebase to modern idioms and stdlib APIs.
  Run `go fix ./...` on a clean worktree as a standard modernization pass (alongside `gofmt`, `go vet`,
  `golangci-lint`) and review the diff — it can touch many files. The old obsolete fixers were removed.
- **`//go:fix inline` migrations.** Annotating a function with `//go:fix inline` makes `go fix` rewrite (inline) all its
  call sites. When deprecating or renaming an exported symbol in a shared Alaa library/SDK, keep a thin equivalent shim
  annotated `//go:fix inline` so downstream services migrate mechanically with `go fix ./...` instead of hand-edits.
- **`go tool doc` / `cmd/doc` deleted.** Use `go doc` (same flags, args, behavior). Update Makefiles, CI steps, and
  images that shelled out to `go tool doc`.

## Runtime, GC & performance

- **Green Tea GC is the default.** Expect a 10–40% reduction in GC overhead on GC-heavy programs, plus ~10% more on
  newer amd64 (Ice Lake / Zen 4+) via vector-instruction scanning — exactly the win for high-concurrency chi/Fiber APIs,
  workers, and RabbitMQ consumers that allocate many small short-lived objects. Do **not** set
  `GOEXPERIMENT=nogreenteagc` in production images; the default is what Go tests and hardens (the opt-out is expected to
  be removed in 1.27). Still reduce allocation churn (`sync.Pool` for hot buffers, preallocated slices) — GC cost scales
  with allocation volume. Re-baseline p99 latency and GC metrics after upgrade.
- **More slice backing stores stack-allocate.** An escape-analysis improvement keeps more `make([]T, n)` results on the
  stack — a free win in hot request paths and encode/decode buffers. Write `make` with a concrete length/cap and avoid
  forcing escape (storing/returning the slice) so the compiler can prove non-escape.
- **cgo baseline call overhead reduced ~30%.** Relevant only when crossing the cgo boundary; cgo is still far more
  expensive than a pure-Go call. Keep standard API services on `CGO_ENABLED=0` for static, distroless, cross-compilable
  builds; do not adopt cgo just because it got faster.
- **New scheduler metrics under `runtime/metrics`:** `/sched/goroutines/...` (counts by state),
  `/sched/threads:threads`, `/sched/goroutines-created:goroutines`. Scrape these into OpenTelemetry/SigNoz and prefer
  them over polling `runtime.NumGoroutine`; goroutine-state saturation and creation rate are strong signals for
  goroutine pileups and per-request leaks. Add alerts for latency-sensitive services.
- **64-bit heap base randomization is on by default** (ASLR-style hardening, most valuable with cgo). Leave it enabled;
  the build-time opt-out is `GOEXPERIMENT=norandomizedheapbase64`.
- **Not new in 1.26:** container/cgroup-aware `GOMAXPROCS` (that landed in Go 1.25 — still set pod CPU limits so the
  runtime has a quota to read), and PGO (GA since 1.21 — keep committing a representative `default.pgo`; no 1.26-specific
  PGO change exists).

## Security & TLS posture

- **Post-quantum TLS by default.** `crypto/tls` now enables the hybrid `SecP256r1MLKEM768` and `SecP384r1MLKEM1024` key
  exchanges by default (alongside `X25519MLKEM768`). Do not hard-code `tls.Config.CurvePreferences` in a way that omits
  the ML-KEM hybrids — an explicit list silently disables PQ. Only set `GODEBUG=tlssecpmlkem=0` if a middlebox chokes on
  the larger ClientHello, and record it as a dated drift.
- **Legacy TLS GODEBUGs deprecated, defaults tighten in 1.27.** `tlsunsafeekm`, `tlsrsakex`, `tls10server`, `tls3des`,
  and `x509keypairleaf` are deprecated. In 1.27 the default client/server minimum becomes TLS 1.2, 3DES leaves the
  default cipher suites, legacy RSA key exchange is off by default, and `Certificate.Leaf` is always populated. Use the
  1.26 window to set an explicit `tls.Config.MinVersion = tls.VersionTLS12` (or 1.3), stop re-enabling `tls3des`/
  `tlsrsakex`, and drop manual `Certificate.Leaf` workarounds. Flag any service still needing `tls10server`/`tls3des` as
  a security drift.
- **Crypto key generation ignores user-supplied randomness.** `crypto/rand.Prime`, `crypto/dsa.GenerateKey`,
  `crypto/ecdh.Curve.GenerateKey`, and `crypto/ed25519.GenerateKey` (with `nil`) now always use a secure source. Remove
  any custom/deterministic `rand.Reader` passed into key generation — it is now a no-op. For deterministic crypto tests
  use `testing/cryptotest.SetGlobalRandom`, not a fake reader. The `GODEBUG=cryptocustomrand=1` escape hatch is
  temporary; `crypto/ecdsa` `big.Int` key fields are deprecated.
- **New KEM and RSA APIs.** `crypto` adds `Encapsulator`/`Decapsulator` KEM interfaces (program against them for
  algorithm agility); `crypto/mlkem` is ~18% faster; `crypto/rsa` adds `EncryptOAEPWithOptions` and **deprecates PKCS#1
  v1.5 encryption padding** — prefer OAEP and treat remaining v1.5 encryption as tech debt. New package **`crypto/hpke`**
  implements Hybrid Public Key Encryption (RFC 9180). `crypto/sha3` zero value is a usable SHA3-256;
  `crypto/subtle.WithDataIndependentTiming` no longer pins the goroutine to its OS thread.
- **FIPS 140-3 module v1.26.0.** Select with `GOFIPS140=v1.26.0`; run under `GODEBUG=fips140=only` to make non-approved
  crypto fail. New `crypto/fips140.WithoutEnforcement`/`Enforced` let you carve out a single non-approved call inside an
  otherwise enforced process — wrap only the exact call, keep it audited, log `Enforced()` in a startup self-check.
- **`crypto/tls.ClientHelloInfo.HelloRetryRequest`** marks a retried handshake in `GetConfigForClient`/`GetCertificate`
  callbacks — use it for observability (HRR often signals a group mismatch from the new PQ hybrids), not authorization.

## Standard library to prefer by default

- **`errors.AsType[T]`** — generic, type-safe replacement for the `errors.As(err, &target)` pointer dance; cleaner and
  compile-time-checked for error-envelope mapping (domain error → HTTP status/code). Migrate opportunistically.
- **`slog.NewMultiHandler`** — fan one `slog.Logger` to multiple sinks (JSON to the log pipeline plus an OTel/SOC
  exporter) without a hand-rolled tee handler. Keep the JSON handler the canonical machine-readable sink with consistent
  attribute keys.
- **`os/signal.NotifyContext` reports the cause** — it cancels via `context.CancelCauseFunc`, so `context.Cause(ctx)`
  tells you which signal (SIGTERM vs SIGINT) triggered graceful shutdown; log it to distinguish orchestrated restarts
  from operator interrupts. No API break.
- **`net/http` changes to verify:** the `Client` now scopes cookies to `Request.Host` (re-check services where `Host`
  differs from the dial target behind the gateway); `ServeMux` trailing-slash redirects are now **307** (method/body
  preserved — update clients/tests that asserted 301); `HTTP2Config.StrictMaxConcurrentRequests` makes HTTP/2
  connection-pool behavior predictable for high-concurrency upstreams (load-test the chosen mode).
- **`net/url.Parse` is stricter** — it rejects malformed host colons; add URL-parsing tests before upgrading any service
  that ingests external URLs. `GODEBUG=urlstrictcolons=0` is a temporary escape hatch, not a fix. New context-aware
  `net.Dialer` dial methods and `netip.Prefix.Compare` are available.
- **Efficiency wins (no code change):** `io.ReadAll` allocates less and returns a minimally sized slice (lower GC
  pressure on request-body handling); `fmt.Errorf` is cheaper for unformatted strings; `bytes.Buffer.Peek(n)` gives
  lookahead without consuming (useful for framing parsers).

## Testing

- **`t.ArtifactDir()` + `go test -artifacts`** — write golden files, captured payloads, and failure dumps to
  `T/B/F.ArtifactDir()` (persistent, unlike auto-cleaned `t.TempDir()`), run `go test -artifacts -outputdir=...` in CI,
  and wire the output dir into the pipeline's artifact upload.
- **`for b.Loop() { ... }`** — standardize on it over `for i := 0; i < b.N; i++`; in 1.26 it no longer blocks inlining of
  the loop body, so numbers better reflect production. Re-baseline existing `b.Loop` benchmarks after upgrading.
- **`testing/cryptotest.SetGlobalRandom`** — the sanctioned way to get reproducible crypto in tests now that key-gen
  ignores injected randomness. Test-only; never link into production binaries.
- **Not changed by 1.26:** `testing/synctest` (stable since 1.25), `testing.T.Context` (since 1.24), and fuzzing — use
  them as already-stable facilities and verify their API against the 1.24/1.25 notes, not the 1.26 page.

## Experimental — gate, do not ship in cross-platform production

- `GOEXPERIMENT=goroutineleakprofile` — a profile that reports goroutines permanently blocked on a concurrency
  primitive. Excellent in staging/soak tests and CI to catch leaked goroutines (forgotten cancellation, blocked channel
  sends); keep it out of the default production build.
- `GOEXPERIMENT=simd` — the experimental amd64-only `simd/archsimd` package. Only for CPU-bound data planes; gate behind
  build tags with a portable fallback.
- `GOEXPERIMENT=runtimesecret` — the `runtime/secret` package for securely erasing secret temporaries. Track for future
  adoption in key/token/crypto paths; keep current secret-handling discipline meanwhile.
- `GOEXPERIMENT=jsonv2` — `encoding/json/v2` remains the experiment from Go 1.25 (not changed in 1.26). Keep production
  JSON contracts on stable `encoding/json` until json/v2 is promoted; confirm status on pkg.go.dev before adopting.

## Adoption rules for this pack

1. Match the repo's `go` directive; raise it only for a feature the code actually uses and CI supports, and say why.
2. Run `go fix ./...` (plus `gofmt`, `go vet`, `golangci-lint`) as a reviewed modernization pass; never blind-commit it.
3. Use `new(expr)` for pointer-to-value fields instead of temp-address or `ptr`/`ToPtr` helpers, once `go >= 1.26`.
4. Reach for `errors.AsType[T]`, `slog.NewMultiHandler`, and `context.Cause` in the shutdown path by default.
5. Do not disable Green Tea GC or heap-base randomization in production; re-baseline latency/GC metrics after upgrade.
6. Scrape the new `runtime/metrics` scheduler metrics; alert on goroutine-state saturation and creation rate.
7. Set an explicit `tls.Config.MinVersion` and keep ML-KEM hybrids enabled; treat `tls3des`/`tlsrsakex`/`tls10server`
   reliance as a security drift to remediate before Go 1.27.
8. Remove custom `rand.Reader` from key generation; use `testing/cryptotest.SetGlobalRandom` for deterministic tests.
9. Prefer OAEP over PKCS#1 v1.5 encryption; use `crypto/hpke` for HPKE and the KEM interfaces for algorithm agility.
10. Add URL-parsing tests before upgrading services that ingest external URLs (stricter `net/url.Parse`).
11. Write persistent test outputs to `t.ArtifactDir()`; benchmark with `for b.Loop()` and re-baseline.
12. Keep every experimental `GOEXPERIMENT` feature behind gating with a portable fallback; never ship it as a default.
