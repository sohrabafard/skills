# GPT-6 in Codex

Use this reference for the active GPT family. For an explicit user request for a legacy
model, read `references/90-model-selection.md`; refresh any legacy fact from its official source.

## Three separate contracts

1. **Official capability:** model pages describe model and API behavior. They do not prove
   that an account, Codex host or custom agent exposes that capability.
2. **Runtime capability:** the current Codex tool schema and effective configuration decide
   available models, efforts, tools, permissions and override behavior. Read
   `references/11-codex-runtime-features.md` before you rely on them.
3. **Capability registry:** `assets/codex-model-policy.json` owns supported-pair evidence and the model-neutral identity of each role and artifact. Its dated snapshot does not guarantee host availability. When you select a task pair, read `references/90-model-selection.md`; it names the owner of task allocation.

## Source starting points and task routing

Official Codex guidance recommends GPT-6.1 Sol for complex coding and demanding agents. It names Luna high and Astra low as broad starting points. The specific selector gives different cells for each workload and priority. Read `references/90-model-selection.md` for the complete source guidance and the owner of task allocation. Recommendations remain uncalibrated hypotheses; they establish neither comparative quality nor availability.

## Prompt design

- Give the outcome, scope, authority, required evidence, output shape and stop conditions.
  Keep a fixed order only where order affects correctness.
- Use a small router and precise triggers; load references when their condition applies.
  Preserve the required facts and exception paths when you remove duplicated instructions.
- Keep task-relevant tools, and keep examples that resolve a real ambiguity. Check task quality,
  evidence and scope compliance before you credit lower token use or fewer calls.
- Advisory requests authorize inspection and reporting. Requested implementation authorizes
  scoped local edits and non-destructive validation. Installation, commit, merge, publication,
  deployment, destructive actions and external writes require the applicable explicit authority.
- Before you remove verification language, read `references/80-subagent-authoring.md`; it
  decides which focused checks and independent gates survive.
- For reversible low-impact edits, require discriminating evidence appropriate to the change;
  generic test reminders do not create a new suite. Repository-mandated checks still apply.
- Give explicit delegation scope when delegation is authorized; the runtime's current tools
  and higher-priority instructions decide whether and how it can execute.

## API is not the Codex harness

API reasoning parameters, asynchronous tool calling, cache controls, Pro modes and API
multi-agent features do not become Codex configuration keys by appearing in a model guide.
Verify each on the surface being configured. The GPT-6.1 Sol API page lists `low`, `medium`,
`high`, `xhigh` and `max`, excluding `none` and `minimal`; the active Codex host schema also
lists `ultra`. Do not transfer Codex `ultra` to API configuration or infer tool access from a model ID.
Do not transfer an API `none` setting to Codex when its active host exposes only reasoning efforts.
