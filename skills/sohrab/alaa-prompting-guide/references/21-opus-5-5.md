## Prompting and calibration

Start effort at the documented default. Do not inherit an older generation's pin. Increase effort only after you exclude context, tooling and specification problems and quality still falls short. Higher effort can add long turns and token cost. Vendor benchmarks cannot establish a gain for this pack.

Current default effort is medium. The official launch's headline benchmarks mostly use max, with Terminal-Bench at xhigh. Those measurements do not prescribe max or xhigh for every coding lane. The levels low, medium, high, xhigh and max are all supported, subject to actual host controls. Keep workload selection separate from benchmark settings.

Give the desired outcome, complete task context, scope, authority, acceptance criteria and
stop conditions. The official advice to remove generic "think carefully" reminders is chat-specific. Do not generalize it into a ban on task-specific agentic reasoning or required checks. Keep required retrieval, focused tests and independent acceptance gates. Before you remove verification language, apply the authority test in `references/80-subagent-authoring.md`. Define response length, file length and progress cadence separately from reasoning effort.

For delegation wording, read `references/06-invocation-and-composition.md`; explicit
independent scopes and host permissions still govern what may run.

## API migration boundary

Thinking is always adaptive on this model. Existing API clients must check the migration guide for unsupported disabled or manual thinking, forced tool choice and assistant prefill. They must also preserve returned thinking blocks in tool loops. Recount output budgets before you carry old limits forward. API history, caching and thinking controls are not automatically Claude Code settings; read `references/41-claude-code-runtime-features.md` for that surface.
