# GPT-5.5

API model id `gpt-5.5` (ChatGPT surfaces it as GPT-5.5 Thinking / Pro / Instant). OpenAI's current flagship reasoning model, positioned for agentic coding, computer use, long-horizon tool-use, and knowledge work: "instead of carefully managing every step, you can give GPT-5.5 a messy, multi-part task and trust it to plan, use tools, check its work, navigate through ambiguity, and keep going." It reaches strong results with fewer reasoning tokens than GPT-5.2/5.4 at the same effort setting, and adds an `xhigh` reasoning-effort tier those did not have. Context window ~1,050,000 tokens, 128,000 max output tokens.

Treat GPT-5.5 as a new family to tune for, not a drop-in replacement for older 5.x prompts — start from a lean baseline and re-tune verbosity, reasoning effort, and tool descriptions against real examples rather than porting an old prompt stack wholesale.

## The two independent knobs

- **`text.verbosity`** (low / medium default / high) — controls output length and detail, not reasoning depth. GPT-5.5's baseline is already more concise than earlier models, so `low` here is proportionally more concise than `low` used to be on GPT-5.4 — recalibrate, don't assume parity. Explicit prompt instructions override the verbosity setting when they conflict. Default to plain paragraphs; use headers/bold/bullets sparingly, only where structure genuinely aids comprehension.
- **`reasoning.effort`** (none / low / medium default / high / xhigh) — `medium` is the recommended balanced starting point for quality, reliability, latency, and cost. `none` is only for latency-critical tasks that don't need reasoning. Reserve `high`/`xhigh` for tasks where you've measured a real quality gain, not as a default upgrade.

**The one counter-intuitive rule to hold onto:** higher reasoning effort is not automatically better. If a task has conflicting instructions, weak stopping criteria, or open-ended tool access, higher effort can produce *more* overthinking, not less. Effort is a last-mile knob — fix the prompt's success criteria and retrieval/tool boundaries first, then reach for effort. When migrating a prompt that used `high`/`xhigh` out of habit on GPT-5.2/5.4, re-benchmark at `low`/`medium` first, since GPT-5.5 needs fewer reasoning tokens to hit the same bar.

## Tone

Default baseline style is efficient, direct, task-oriented — a good default for backend/production work, but not automatically right for customer-facing or conversational products; add explicit personality, warmth, and formatting guidance for those. Split tone instructions into two short, separate blocks rather than one long one: **personality** instructions shape the user experience, **collaboration** instructions shape task behavior. GPT-5.5 interprets prompts literally and thoroughly, so specific instructions beat implied vibes, especially for long tool-heavy runs.

## Prompting techniques that matter most

- **Outcome-first, not process-heavy.** Describe the target outcome, constraints, evidence, and required output shape. Avoid step-by-step process instructions unless the exact path genuinely matters — "shorter, outcome-first prompts usually work better than process-heavy prompt stacks."
- **Explicit success criteria and stopping rules** are the real lever against both premature stopping and rambling overthinking — more effective than raising `reasoning.effort`.
- **Persistence instruction for agentic tasks**, carried forward from the GPT-5 family and still current in spirit: tell it not to yield back to the user until the problem is actually solved, to make and document reasonable assumptions instead of pausing to ask, and to keep going through uncertainty. GPT-5.5's own default bias already favors action over stopping for clarification, so this instruction reinforces a native tendency rather than fighting it — but pair it with concrete stopping criteria so "keep going" has an actual exit condition.
- Be explicit about reuse policy, delegation, test expectations, and exactly when to escalate to the user versus proceed — GPT-5.5 follows these literally.
- Replace legacy ALWAYS/NEVER absolutes with decision rules the model can reason against, for anything that is actually a judgment call.
- Put tool-usage guidance in the tool's own description/schema, not buried in system instructions — GPT-5.5 uses large tool surfaces more precisely that way.
- Use structured/schema-constrained outputs instead of describing a JSON shape in prose.
- For prompt caching: put static content (instructions, tool defs) first and volatile content (the user's turn, retrieved evidence) last; drop the current date unless actually needed, since it busts the cache prefix every call.
- For multi-step tasks, add a preamble instruction: send a short user-visible acknowledgment plus the first step before the first tool call, so long runs don't look frozen.

## Ready-to-use system/developer prompt fragment

```text
You are an agent - keep going until the task is completely resolved before ending your turn.
Only stop when you are sure the problem is solved, or genuinely blocked with no reasonable path forward.
Do not pause to ask the user to confirm an assumption you can reasonably make yourself - decide, proceed,
and record the assumption for the user afterward. Prefer outcome-first instructions over dictating every step.
Done means: <state the concrete, checkable success criteria here>.
```

Pair this with `reasoning.effort: medium` as the starting point and only raise it after you've tightened the success criteria and confirmed the task is genuinely hard, long-horizon, or architecture-sensitive.

## Caveats

The verbatim "you are an agent, keep going" persistence wording traces to the original GPT-5 cookbook prompting guide, not a page confirmed to be GPT-5.5-specific — treat it as carried-forward family guidance that OpenAI's own docs site still surfaces, not a freshly-authored GPT-5.5-only example. The main marketing announcement page returned an error on fetch and was not read directly; secondary/search-sourced framing from it should be treated with slightly less confidence than the directly-fetched API docs. Do not assume GPT-5.5 is a drop-in replacement for GPT-5.2/5.4 prompts.
