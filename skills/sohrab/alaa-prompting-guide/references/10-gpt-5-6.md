# GPT-5.6

Use `gpt-5.6` for the GPT-5.6 Sol frontier tier. It has a 1,050,000-token context window, 128,000 max output tokens, and a February 16, 2026 knowledge cutoff. Treat these limits and availability as volatile.

## Model and effort

- `gpt-5.6` aliases `gpt-5.6-sol`; use Sol for frontier capability, `gpt-5.6-terra` for intelligence/cost balance, and `gpt-5.6-luna` for efficient high-volume work.
- Prefer the Responses API for reasoning, tools, and multi-turn workflows.
- `reasoning.effort` supports `none`, `low`, `medium`, `high`, `xhigh`, and `max`; default is `medium`. Preserve the current GPT-5.5/5.4 setting during migration, then test one level lower. Reserve `max` for measured quality-first gains.
- Enable Pro with `reasoning.mode: "pro"`; do not invent a Pro model slug or prompt the model to "think harder." Mode and effort are independent.
- For output length, prioritize required content instead of using generic "be concise" instructions. If an API surface exposes `text.verbosity`, treat it separately from reasoning and verify its current schema.

## Prompt contract

- Start with the smallest prompt and task-relevant tool set that passes representative evals; add instructions or examples only for observed gaps.
- State the outcome, relevant context, constraints, required evidence, success criteria, output shape, and stopping condition. Avoid process scripts unless order is part of correctness.
- Define authority once: inspection/reporting requests do not authorize implementation; change requests authorize scoped local edits and non-destructive validation; external writes, destructive actions, purchases, and material scope expansion require confirmation.
- Keep every required fact, decision, caveat, and next step. Trim introductions, repetition, generic reassurance, optional background, and duplicated permission warnings first.
- Use lightweight, task-specific structure. Replace generic warmth with concrete tone such as direct, tactful, and free of canned reassurance.
- For agentic work, require persistence until verified completion or a genuine blocker; allow reasonable assumptions within scope and require disclosure afterward.
- State reuse, delegation, tests, escalation, and parent-agent reconciliation explicitly. Replace legacy ALWAYS/NEVER wording with decision rules where judgment is required.
- Put tool inputs, outputs, errors, and routing constraints in tool descriptions/schemas. Prefer structured outputs over prose-described JSON.
- For long tool runs, require one short preamble before the first call. Put stable prompt/tool content before volatile user or retrieved content for cache reuse.

## GPT-5.6 tool features

- Programmatic Tool Calling (PTC) fits bounded filtering, joining, ranking, aggregation, validation, or reduction across eligible tools. Define the bounded stage, tools, output schema/evidence, concurrency/retry/stop limits, and direct-call handoff. Use direct calls when results change the next decision, approval is required, or native citations/artifacts must survive.
- Multi-agent is a Responses API beta. Use it only for cleanly independent workstreams; state authorization, lane ownership, limits, and synthesis responsibility.
- Use `reasoning.context: all_turns` with `previous_response_id` when goals and assumptions remain stable; use `current_turn` when prior reasoning is stale. Preserve returned reasoning items when manually managing history.
- Implicit prompt caching still works. Use explicit caching only when measured; monitor cache reads/writes and avoid volatile prefixes.

## Minimal reusable fragment

```text
Deliver <outcome> using <context/tools> within <scope>.
Preserve <invariants>. Done means <checkable criteria> verified by <evidence>.
For analysis/review, inspect and report only. For requested changes, edit in scope and run non-destructive checks.
Confirm before external writes, destructive actions, purchases, or material scope expansion.
Continue until done or genuinely blocked; then report the blocker and what would unblock it.
Keep required facts, caveats, decisions, and next actions; trim repetition and optional background first.
```

## Verification and caveats

Benchmark task success, answer completeness, evidence, tokens, latency, and cost on representative work. Fewer tokens/calls are improvements only when the final answer still meets the quality bar. GPT-5.5 prompting remains broadly applicable, but migration is a tuning pass, not only a model-string change; re-fetch official docs before relying on volatile limits, prices, beta status, or parameter behavior.
