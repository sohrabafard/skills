# Current Kit Capability Map

Verify every symbol and default against the live kit before use. Start from `CONTRACTS.md`, `docs/RUNBOOK.md`,
`docs/scaffold-cli-reference.md`, `go.mod`, `Makefile`, and source; this map is navigation, not an alternate
contract. Identity: module `git.alaatv.com/vk/alaa-go-chi`; as of this skill revision the latest released tag is
`v0.3.1` with a breaking `v1.0.0` candidate staged — always read `CHANGELOG.md` for the current state.

## Bootstrap and generated service

- Create with `alaa-go-chi new service <name> --parent-dir <dir>`; legal flags/defaults live in
  `docs/scaffold-cli-reference.md` (`--module-path`, `--kit-version`, `--tier direct|small|medium|large`,
  `--kit-replace`, `--no-git`, `--force`, …). Normal generation pins a released kit and emits no committed local
  `replace`.
- Generated service owns `main.go` and domain composition; kit owns shared runtime behavior. Standard commands are
  `serve`, `consume`, `dispatch`, `relay`, `migrate`, `seed`, `topology`, and `ops`; wire only used roles.
- Scaffold includes strict HTTP/trust/readiness/metrics posture examples, config, migrations/seeders, API fixtures,
  OpenAPI/Postman, docs skeleton, Docker/shared infra, Helm/Arvan shapes, GitLab CI, hooks, lints, and contract
  tests, plus the consumer `AGENTS.md`/`CLAUDE.md` policy pair.
- Placeholder routes are examples to replace with thin handlers/use cases. Route truth, OpenAPI, fixtures, Postman,
  and bidirectional API coverage must remain synchronized via `make api-contract`.
- No released scaffold flags currently prune PostgreSQL/RabbitMQ. A manually composed datastore-free service uses
  `configkit.WithoutPostgres()`/`WithoutRabbitMQ()` and matching `contracttest.DocSurfaces`; never fabricate DSNs.

## Runtime and contracts

- `configkit`: typed boot config, env/dotenv/secret-reference precedence, redaction, lane opt-out, generated env
  block. `BYPASS_GATEWAY_PROOF` is a strict boolean that defaults to `true`. In bypass mode the loader does not
  look up, resolve, or retain `GATEWAY_PROOF_HEADER`, `GATEWAY_PROOF_SECRET`, or `GATEWAY_PROOF_SECRET_FILE`;
  this mode is valid only behind an independently verified gateway-only network boundary. Setting the bypass to
  `false` restores the proof contract: the header must be non-blank and syntactically valid, the secret must resolve,
  and `RequireGatewayProof()`/`ValidateGatewayProof` fail boot when the proof configuration is incomplete. Generated
  multi-role binaries wire the same typed decision into `serve`; worker/migrate/seed roles do not receive the secret.
- `httpkit` + chi: hardened server/router, strict/body-bounded JSON, stable envelopes, route inventory, correlation.
- `trustkit`: `TrustCtx`, UUIDv7 project and positive int64 user, permissions, TOTP, four route postures, metrics
  proof. When `BYPASS_GATEWAY_PROOF=true`, the gateway-proof middleware deliberately skips proof validation and
  relies on the gateway-only network boundary; when `false`, the existing constant-time proof validation and
  unauthorized response remain active. Routes assemble through `trustkit.NewPosture(servicePermissions())`; the
  scaffold generates
  `trustkit.DenyAllPermissions` as the fail-closed placeholder, and a consumer replaces **only** that permission-map
  seam with the map generated into `internal/authz/permissions_gen.go` from `alaa-permission-catalog` via the
  `alaa-permission-generator` skill (which also syncs the `auth` seed). Never hand-write permission names or bitmap
  ids, never edit a `Code generated by alaa-permission-catalog. DO NOT EDIT.` file, never define a local posture.
  `X-Access` is a base64url-nopad bitmap: permission id `n` maps to bit index `n-1`, packed LSB-first.
- `errkit`: typed domain/application errors, append-only codes, single boundary mapping.
- `readykit`: liveness plus required/degraded/informational readiness and `ops ready --json`.
- `runkit`: lifecycle ownership and ordered stop-intake/drain/flush/close shutdown for the standard commands.
- `idkit`/`audiencekit`: UUIDv7 public IDs/Crockford rendering and canonical audience predicate/vectors.

## Data, messaging, work

- `pgkit`: pgx/v5 two-lane runtime/admin DSNs, PgBouncer tiers/budgets, transactions, composed goose migrations,
  keyset/testdb helpers. DDL/session operations use the direct admin lane. `pgkit.ComposeMigrations` orders service
  and kit migration sources by owned version bands — never renumber or hand-merge generated/kit series.
- `rediskit`: optional cache transport with context-enforced command timeout, disabled hidden retries, bounded
  connections/dials, mandatory entry TTL, finite registered persistent version keys, privacy-safe client spans,
  degraded readiness, and bounded cache/transport/pool metrics. Redis is never truth. Compose explicitly:
  `rediskit.ConfigFrom(cfg)` → `rediskit.NewMetrics(obs.Metrics.Registerer(), cfg.AppName, cfg.AppEnv)` (fail boot
  on error) → `rediskit.NewClient(cfg, rediskit.WithTransportMetrics(m))` → `rediskit.NewCache(client,
  rediskit.WithCacheMetrics(m))`, optional `rediskit.NewInvalidator(client, registeredVersionKeys...)`, and
  `client.ReadyCheck(...)` registration. In the service contract test call
  `contracttest.AssertMetricNamesStable(t, obs.Metrics.Gatherer(), cfg.AppName, rediskit.MetricNames())`; the same
  private registry is served by `/metrics`. The default tracer is production-safe; use `WithTracer` only for an
  intentional SDK/test override.
- `mqkit`: RabbitMQ connection/reconnect, confirming publisher, envelope/traceparent, topology, consumer shell,
  durable receipt/idempotency semantics, DLQ and bounded replay behavior.
- `outboxkit`, `jobkit`, `seedkit`: one-transaction durable outbox, bounded skip-locked workers, and locked
  run-twice-safe seeders.

## Controlled operations and Tier 2

- `ctlopskit`: durable ControlledOps state, approval/TOTP/audit/admission, execution fencing, append-only schema.
- `bulkkit`: bounded bulk descriptors/engine, policies, claims/leases, partial/atomic behavior, metrics, job/MQ
  adapters.
- `ops/ops.yaml` is consumer-authored Tier-2 intent. `alaa-go-chi gen` emits the generated registry/bindings with a
  kit-version stamp and refuses a binary/pin mismatch. Guard drift with `make tier2-drift`; never hand-edit outputs.
- `refops` is kit-local evidence, not a service template.

## Contract, generation, CI, and proof tooling

- `contracttest`: reusable kit-behavior assertions for envelopes, trust/TOTP, readiness, route inventory, docs, and
  canonical vectors. Select `DocSurfaces` to match deliberately disabled PostgreSQL/RabbitMQ/scaffold surfaces; the
  zero value verifies the complete default service contract.
- `apicontractkit` + `apicontractkit/postman`: merge route truth with authored OpenAPI, validate bidirectional
  coverage, require fixtures for exactly the responses an operation documents, and generate Postman artifacts.
  Supported request parameters are primitive standard path/query shapes; unsupported serialization fails closed.
  Response projection requires exact concrete statuses, one media type, non-colliding fixture files, and a
  1..128-byte lowercase `x-fixture-case` slug; statuses outside 2xx/400/401/403 require an explicit case.
  `postman.Options.GatewayProofHeader` defaults to `X-Gateway-Proof`; the CLI flag is `-gateway-proof-header`, and
  generated `make api-contract` forwards the effective header to route inventory and Postman generation. Service
  `api/postman/extract.yaml` may chain known operations into variables (operation/name/path required; reserved or
  duplicate names fail). Service `api/fixtures/` are authored contract inputs; edit them with route/OpenAPI
  changes. Never hand-edit generated Postman outputs or `scaffold/testdata/` goldens.
- `scaffold`: generator-owned source lives in `scaffold/templates.go`; `scaffold/testdata/` goldens change only
  through generator/update tests.
- `genkit`: Tier-2 ControlledOps/bulk code generation from `ops/ops.yaml`, with kit-version stamps and drift
  checks. Generated bindings/registries are outputs; diagnose pin/tool mismatches instead of copying or editing.
- `cikit`: owns generated GitLab phase jobs and CI evidence shape. A template is not proof of remote enforcement;
  runner-backed jobs or the documented local-smoke vocabulary provide the evidence.
- `linttools` and `cmd/alaa-*lint`: enforce pooled-lane boundaries, struct tags, metric names, UUID defaults, and
  text normalization. Run the repository targets; do not weaken a rule or bypass a finding to make a gate green.
- `chaos`: kit-local failure-injection proof (Toxiproxy-based) for bounded degradation/recovery. Use the tagged
  chaos gate when a change touches failure semantics; it complements, never replaces, real infra truth tiers.

## Observability, security, deployment, CI

- `obskit`: JSON slog fields/events, OTel traces/metrics/exemplars, SigNoz-compatible correlation, bounded core
  metric names, and Sentry for panics/programming faults only. Never label/log IDs, raw paths/payloads, PII,
  secrets, or error text. Dashboard/alert renderers and Prometheus rule checks are kit-owned; engine/rediskit
  metric vocabularies are closed registries and metric-name lint blocks raw/re-prefixed names.
- Generated Docker/Compose/Swarm/Helm/Arvan shapes preserve non-root containers, probes, role separation, secret
  mapping, PgBouncer topology/budgets, migration/seed jobs, NetworkPolicy, PDB/HPA/rollout safety. Compose keeps one
  implicit `serve` replica. Swarm defaults `serve` to three replicas; its base stack uses bypass mode and its
  `stack.gateway-proof.yaml` enforcement overlay requires the external `gateway_proof` secret. Helm defaults `serve`
  to three replicas and `autoscaling.minReplicas` to three, renders the proof secret reference only in enforcement
  mode, requires `secret.existingSecretName` at render, disables service-account token automount, hardens all
  containers/jobs, and uses zero-unavailable rolling updates plus soft hostname spreading; PDBs render only when the
  effective minimum is at least two. The opt-in CPU HPA owns serve replicas (Deployment omits `spec.replicas` while
  enabled) while preserving the default three-replica floor. Generated NetworkPolicy is opt-in and is not evidence
  that bypass mode's gateway-only boundary exists. Enable HPA
  only after `autoscaling/v2`, metrics-server, resource requests, and min/max capacity are verified; current Arvan
  scaling remains manual until live discovery proves autoscaling control. Adopting the required secrets, replica
  defaults, and trust checks from `v0.3.1` is a major migration, not an additive regeneration. Four-nines work
  still requires a medium/large pooled tier and live Arvan placement, load, dependency-failover, and SLO-burn
  proof; generated controls alone are not SLA certification.
- **Shared infrastructure is platform-shared, never service-owned.** Generated services attach to one canonical
  shared-infra instance identified by `DOCKER_SHARED_INFRA_PROJECT` (default `alaa-shared-infra`),
  `DOCKER_SHARED_NETWORK_NAME` (default `alaa-shared-network`), and `DOCKER_VOLUME_PREFIX`; the generated
  `deploy/shared-infra/compose.yaml` and wrappers provision it on demand via `PG_PROVISION`/`REDIS_PROVISION`/
  `RABBITMQ_PROVISION` (default `true`; production fails closed unless all are explicitly `false`), with the
  reuse-if-healthy gate: if the shared project already runs the needed services, reuse untouched — never recreate,
  never create a service-local sibling infra project. `ALAA_SHARED_INFRA` names the shared-infra source;
  provisioning always implies migrate; `AUTO_MIGRATE`/`AUTO_SEED` default `false` and seeders are
  idempotent-by-contract.
- Go local-runtime generation is owned by `scaffold/templates.go`, not the Laravel `service-runtime-kit`; the two
  generators deliberately mirror one project/network/volume identity and reuse contract so Go and Laravel services
  reuse one Postgres/Redis/RabbitMQ set (owner decision 2026-07-16). Changes to that shared identity, infra set, or
  reuse mechanism must be routed to and validated in both generator owners — see the
  `service-runtime-kit-governance` skill for the Laravel-side counterpart.
- GitLab templates expose phase gates, but real remote enforcement exists only after an assigned runner job
  passes. Until then use the accepted vocabulary: `local_ci_smoke_passed; runner_contract_pending`.
