# Output calibration routing

This skill owns output shape and context economy. Before making a model-specific claim or
choosing model and effort, read `/alaa-prompting-guide` and follow its conditional topic router.
No model profile or effort policy is defined here.

When responses, written artifacts, or progress updates are too long, calibrate those three
outputs separately. State required content and useful cadence; preserve evidence, caveats,
findings, blockers, and the user's requested detail. Do not use reasoning effort as a verbosity
control or infer that lowering effort will meet an output-length target.

When tool output dominates context, bound retrieval at the source and keep a path to useful
full evidence. Do not repeat discovery to appear thorough. A shorter report is not evidence of
better reasoning, and fewer tool calls do not prove equivalent coverage.

Before removing validation instructions, distinguish focused implementer checks, independent
acceptance gates, and redundant repetition. Preserve the first two. Remove repeated checks only
when no new change, failure, or unresolved concern justifies them.

Evaluate a calibration change on representative tasks with the same required content and
acceptance criteria. Keep it only when coverage and authority compliance survive. The prompting
owner supplies current model guidance; this file supplies no universal behavioral guarantee.
