# Shared Consumer Contract

These rules hold for every consumer of the permission catalog in every language. They are stated here once; the
per-language references add only what that language needs and never restate these.

## The six rules

1. **Commit the generated artifact at the exact declared `source_path`.** Drift compares the applied file against
   generated output byte for byte after line-ending normalisation. A shortened, moved, or equivalent path is not
   accepted, and a moved path also breaks the importer, which reads the declared path.
2. **Allow no override, of any kind.** No environment variable, no JSON or YAML file, no database row, no hand-written
   map, no runtime fetch of the catalog, and no feature flag may change the permission map a consumer uses. There is
   exactly one map per consumer and it is the committed generated file. When a change is needed, change the catalog.
3. **The bit contract.** Ids are one-based and `bit_index = bitmap_id - 1`; both are enforced in the catalog as fatal
   findings. Bits are packed **least-significant-bit first within each byte**, and the bitmap travels as **raw unpadded
   base64url**: id `1` is bit `0` of byte `0`, id `8` is bit `7` of byte `0`, id `9` is bit `0` of byte `1`, and
   `permission_id = byte_index * 8 + bit_index + 1`. Attribution matters here — the catalog project allocates ids and
   emits maps and **never encodes or decodes a bitmap**, so those last two clauses are not enforced by any code in it.
   They rest on the project's `docs/bitmap-contract.md` and on each consuming service's own decoder. The wire format and
   the trust semantics of the header carrying it are owned by `/alaa-services-contract` (`$alaa-services-contract`) and
   `/alaa-trust-gateway-auth` (`$alaa-trust-gateway-auth`); those skills win on any conflict with this paragraph.
4. **Ignore unknown bits; fail closed on zero.** A bit with no entry in this consumer's map grants nothing and is not an
   error, so a token issued against a newer catalog degrades to fewer permissions instead of failing. A **server-side**
   protected request that resolves to zero known permissions is rejected. The one exception is a browser client
   deriving UI hints, where an empty set is a legitimate ready state — see `references/typescript-consumer.md`.
5. **Never hand-edit a generated file.** Files carrying `Code generated by alaa-permission-catalog. DO NOT EDIT.` or
   `This file is auto-generated by alaa-permission-catalog. Do not edit manually.` are generator-owned byte for byte,
   line-ending normalisation aside. Note that generated Laravel **service configs carry no such header** and are
   generator-owned all the same. A hand edit surfaces as `AGGREGATE_CONSUMER_MANUAL_EDIT` for the TypeScript consumer
   and as nothing at all for a PHP config, so the rule is the only protection there.
6. **Re-validate after applying.** Run `import`, then `check-drift --strict`, then `php tests/run.php`, so the importer
   observes the applied artifact and aggregate drift verifies it. Fatal and error counts must be zero before the change
   is reported as done.

What makes each of these tests a real test rather than a replay of the happy path is owned by `/alaa-testing-strategy`
(`$alaa-testing-strategy`), and framework idiom by the per-language skill. The **cases** listed in the three consumer
references are domain facts and stay there.

## The decode is a per-request cost — memoize it once

The decode runs on every protected request in a high-concurrency service, so its cost is a request-path cost.

- **Decode exactly once per request**, at the trusted-context boundary, and store the resulting permission set on the
  trusted-context object every later check reads. No handler, policy, middleware, or repository decodes again.
- Store the result as a **set keyed by permission name** so a check is a single hash lookup, not a scan. Never compare
  by bitmap id in application code, and never re-derive names inside a loop over resources — that is the N+1 shape.
- **Take the decoder from `assets/permission-bitmap/` rather than writing one.** All three canonical implementations
  already satisfy every rule in this file, and `scripts/bitmap-conformance.sh` proves they agree case by case. See
  `SKILL.md`.
- **Cap the encoded bitmap length server-side, at the boundary, before decoding.** The client-side caps described for
  the browser consumer do not protect a service; an untrusted-length input decoded without a cap is unbounded work.
  The cap value belongs to `alaa-services-contract references/22-failure-load-and-deprecation-contract.md`; the bound
  the decode must hold as the catalog grows belongs to `/alaa-algorithms-data-structures`
  (`$alaa-algorithms-data-structures`).
- Under a long-lived worker, never memoize a decoded permission set anywhere whose lifetime outlives the request — not
  a singleton, not a static property, not a `once()`-wrapped service. `laravel-best-practices/rules/caching.md`, an
  upstream skill this repository does not own, heads a section "Use `once()` for Per-Request Memoization"; under Octane
  that returns request 1's authorization set to every later request on the worker. This skill wins on that conflict.

## Observability of the authorization decision

Three signals are required. Name none of the fields here: every field, metric, and event **name** is owned by
`/alaa-services-contract` (`$alaa-services-contract`) and every requirement level and gate by
`/alaa-observability-soc` (`$alaa-observability-soc`). SOC wins on whether a signal is required; the contract wins on
what it is called.

- **Unknown-bit rate.** A counter distinguishing decoded bits that resolved to a known permission from those that did
  not. A rising unknown-bit rate is the only production signal that a consumer's artifact is behind the catalog, and
  rule 4 makes that failure silent by design.
- **Stale-fingerprint detection.** The consumer reports the fingerprint compiled into its artifact so it can be
  compared with the catalog's current fingerprint. This is what turns "which services are running an old permission
  map" from an audit into a query. Never hardcode a fingerprint value anywhere.
- **A denial record carrying the failing permission key.** Every authorization denial records the permission key that
  failed, so a denial is diagnosable without reproducing the request. A denial with no key is not diagnosable.

Never log a raw token, a raw claim, or the raw encoded bitmap. Permission keys are not secrets; tokens are.
