# Go Consumer Pattern

Read `references/shared-consumer-contract.md` first; the six rules there govern this file and are not repeated.
`input_shape` is `go_service_permission_map`. A Go owner may be registered before its map is applied — the importer
tolerates the missing file, which is the clean way to onboard one.

## Emitted surface

The generated file carries `// Code generated by alaa-permission-catalog. DO NOT EDIT.`, a package derived from the
target's parent directory name, a `const` block of `Permission<PascalName> = "<name>"`, unexported forward and reverse
maps, and `MaxPermissionID()`, `PermissionName(id int) (string, bool)`, `PermissionID(name string) (int, bool)`,
`PermissionNamesByID() map[int]string`, and `Decode(access string) (Set, error)`.

The target must end in `.go` and sit in a directory whose name matches `/^[a-z][a-z0-9_]*$/`, or generation exits `2`
with `Cannot derive a valid Go package from generated target [...]`.

**`MaxPermissionID()` is per-file, not per-catalog** — it returns the highest id in *this service's* generated map, and
the generated `Decode` passes it as the decode bound. One shipped service returns `1`. Any id above a service's own
highest generated id is outside that service's decode bound, so allocating a new id and applying only the auth seed
leaves the consuming service unable to decode it. Nothing in the project documents this. When you allocate an id for a
Go service, applying that service's map is part of the same change, not a follow-up.

## Required package contract

The generated file does not compile alone. The owning package must already provide `Set` and `DecodePermissionSet`:

```go
type Set map[string]struct{}

func DecodePermissionSet(
    access string,
    namesByID map[int]string,
    maxPermissionID int,
) (Set, error)
```

Implement it once, in a non-generated file in the same package. It accepts only non-empty input, unpacks bits per rule 3
of the shared contract, ignores ids above `maxPermissionID` or absent from the map, and returns an error when zero known
permissions resolve.

## Integration rules

1. Use the generated constants in middleware and route registration. No permission name string literal and no numeric
   id appears anywhere else in the service.
2. Production decoding calls the generated `Decode`. **Do not export a decoder interface, a decoder variable, or a
   decoder function field from any package.** If a test needs a substitute, the seam is unexported and its only
   production implementation is the generated `Decode`. An exported interface with a live production implementation is
   the override path rule 2 of the shared contract forbids, whatever its stated purpose.
3. Exported map accessors return a copy, as the generated `PermissionNamesByID` does, so a caller cannot mutate
   package state.

## Tests

- Every id and name in the generated map round-trips, and `MaxPermissionID()` equals the highest id in **this** file.
- A bitmap containing this service's lowest and highest ids decodes, including an id in the second byte and one above 64.
- Unknown-only, empty, padded, and invalid-character input each fail closed with an error and no partial set.
- An unknown bit mixed with a known bit keeps the known permission.
- A mutation of the map returned by `PermissionNamesByID()` does not change a later call's result.
- The committed generated file matches a fresh generation.

Run focused package tests plus the repository-native lint, vet, and build gates named by `/alaa-golang`
(`$alaa-golang`).
