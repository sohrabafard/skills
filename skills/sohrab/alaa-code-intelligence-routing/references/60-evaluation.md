# Evaluation contract

Use passive instrumentation as the source of observable tool-event counts. Do not ask the model to reconstruct exact counts from memory.

Hold repository commit, active worktree, prompt, model, effort, permission mode, enabled surfaces, index freshness, Serena health, and proof requirements constant. Use a fresh session per prompt and separate cold from warm runs.

Measure correctness first, then proof coverage, documentation alignment, tool attempts, owner transitions, discovery streaks, subagent starts, and suspected rediscovery. A lower call count with a missed consumer, unsupported claim, broken link, or skipped gate is a regression.

Treat duplicate detection as a heuristic. Review the named gap, staleness state, and artifact transition before calling a sequence waste. Use only stable client-provided usage data; never build a permanent parser over private or unstable transcripts.

Runtime-specific hook events and availability belong to `/alaa-prompting-guide` or `$alaa-prompting-guide`; this skill does not restate them.
