# Evidence-owner routing contract

## Selection and identity

Name the question. Reuse adequate fresh evidence before you select one primary owner; preference never justifies retrieving an answered fact again. "Not configured" and "not applicable" are normal ineligibility, not failures to repair. Any combination of CodeGraph, Serena and Boost is valid, including one alone or none; Boost applies only to Laravel projects. Select lazily from the eligible operations, and skip an absent provider without setting it up. Reuse still-valid capability evidence, and verify only the capability you need; run no blanket health probe. Check the installed operation and its transport, the backend's language coverage, authority, freshness and target identity. Where relevant, identity includes the Git root, worktree and branch, the graph root, the Serena active project, and the intended application, environment and database. Reject evidence from the wrong root or environment for the local claim, except under the lane-worktree rule below.

`SKILL.md` *Operation card* owns the lane-local index. A lane worktree whose index could not be built answers from the main checkout's index, with a different-worktree warning. Accept that result for location, relationships and impact in files the lane has not changed, because the two trees differ only in what changed since the lane branched. Read from the worktree every file the lane changed and every region you will edit. A symbol missing from that result is not proven missing in the lane.

When the scope, branch, service or configuration changes, or the work resumes, check which evidence and capability state stays valid. Invalidate only the affected entries; do not restart covered discovery. Retrieve in parallel only for independently named questions where neither result can change the other's owner, scope, authority or query.

Before selecting Serena, check `.serena` at the resolved project root in the target worktree, not in an arbitrary shell directory. By pack policy, a confirmed absence means Serena is not installed or configured for that project, so it is inactive for routing whatever host binary or MCP endpoint is exposed. Then skip Serena calls, activation and onboarding, use eligible CodeGraph, native or Boost operations, and create no marker or integration without explicit setup scope. An unreadable directory status is unknown, not absent. The directory's presence permits eligibility checks only; it proves no connection, operation support or active-project identity. A copied marker cannot retarget an inherited HTTP binding; verify that binding separately.

Never use CodeGraph MCP or CLI for a Bash or shell question, because CodeGraph does not support these languages (language evidence: `references/90-source-map.md`). This covers discovery, source reads, relationships and impact for scripts, extensionless shell files and embedded shell commands, even in indexed mixed-language repositories. Use bounded native search and read operations and the applicable shell tooling; /alaa-bash-shell owns implementation and validation. Do not probe CodeGraph or retry through another graph operation for these questions. Separate questions about supported non-shell source keep their normal route.

Known identity alone does not select Serena. For an adequate source or structural answer, use eligible CodeGraph first, then eligible Serena, then bounded native evidence. Send required semantics beyond CodeGraph directly to the capable semantic owner, with no futile graph-first call. The other table rows keep their specialized owners. The CodeGraph server and installer own exact usage and the managed instructions. Stack owners keep implementation doctrine. /alaa-repo-docs owns Markdown authoring and alignment, /alaa-workflow owns durable state, /alaa-low-noise owns output budgets, and the installed orchestrator owns fan-out.

Serena and its hooks are not prerequisites for native language operations. Record a known absence once per unchanged capability context, and use an eligible CLI or connected LSP operation without a failed Serena call first. The stack reference owns operation fit; the native reference owns whether an executable or client is eligible.

## Consume evidence

Reuse adequate fresh source, graph paths, metadata and prior results, and never reread them for reassurance. If a region is missing or stale, retrieve only that live region. A new semantic, implementation or runtime question names its missing fact rather than repeat an answered one.

Honor returned provenance: heuristic edges, runtime dispatch boundaries and unexplained path gaps cannot establish a complete call path. Answer a missing dispatch fact through its eligible owner without restarting discovery. A text-search miss does not establish unused code.

Empty, unsupported, stale, paginated or truncated results prove neither absence nor completeness. Complete only the needed continuation pages or uncovered regions. If coverage cannot be established, mark the result unknown or partial. Pagination is not a second reassurance query.

## Finite degraded operation

For each unchanged question, keep the established evidence and every attempted owner-and-operation pair. Before each transition, record the missing fact, the failed capability and its cause, the next eligible operation and the lost guarantee. Mark each attempt before its call. Skip a candidate known to be unavailable or unsupported. Never cycle.

For a failed operation, allow at most one cause-specific, non-mutating repair of health or capability and one materially different retry, when the cause supports them; otherwise advance immediately. Activation, restart, unlock, sync and reindex are not automatic non-mutating repairs. A fallback uses a different eligible operation and never resets a failed operation's budget. Missing coverage alone is not a health failure.

- CodeGraph MCP transport failure: try the CLI only when it is independently usable against the same valid index; a shared stale or bad index skips this detour. Then use supported Serena or backend evidence, then bounded native evidence. Record the lost graph coverage.
- Missing required semantic operation: use an eligible language-native CLI or connected LSP operation that covers the same property, then targeted source for a partial read claim. Diagnostics alone do not establish complete references, and text does not establish refactor safety.
- Missing docs: use version-correct official sources after establishing installed versions.
- Missing native read or parser: use an available equivalent for the actual format and dialect, and state the lost parsing or search coverage.
- Missing Laravel runtime capability: apply the stack owner's independent failure domains for docs, application boot and database.
- Missing proof capability: use an authorized equivalent only if it proves the same property; otherwise report the exact gate blocked.

At exhaustion, give a partial answer or stop the dependent claim; unrelated safe work may continue. A changed question or environment invalidates only the affected state and never justifies repeating valid covered facts.

## Authorized native continuation

Authorized bounded local edits need no configured Serena, gopls or other semantic provider. When provider evidence is missing:

1. Name the behavior and the scope.
2. Use adequate fresh source or returned evidence.
3. Inspect the applicable contracts, callers and tests.
4. Verify the target worktree.
5. Preserve unrelated changes.
6. Inspect the resulting diff.

Run every mandatory native gate under the stack, repository and task proof policy. Source reads alone prove neither complete references, nor a binding-safe rename, nor refactor safety. If a required semantic property of the dependent action or claim lacks authorized equivalent proof, block only that action or claim. Sufficient evidence and the required proof permit the bounded edit without installation.

Provider diagnostics are supplemental unless repository rules or acceptance require a semantic property beyond native proof. Missing optional diagnostics block neither authorized edits nor completion once the mandatory native gates pass; record the gap and the lost guarantee. Do not claim native output is equivalent without evidence. A required property that stays uncovered remains blocked; run the native gates for unrelated safe work.

## Mutation uncertainty

Before a semantic mutation, verify the task authorization, the supported operation and the target identity. After it, inspect the resulting diff and state. After a timeout or uncertain result of a possible mutation, reconcile the actual state before you continue. Never replay the mutation or automatically substitute text editing. If a safe resulting state cannot be established, stop that operation and report the unknown outcome. Fallback expands no authority.

For a failed native gate, permit one cause-specific repair and one retry within task authority; otherwise report the exact failure. No static or provider answer substitutes for an unrun gate.

## Handoff

Carry the established evidence, covered scope, worktree and environment identity, freshness, proof state, attempted operations and unresolved facts. The recipient reuses valid evidence and retrieves only the remaining gaps.
