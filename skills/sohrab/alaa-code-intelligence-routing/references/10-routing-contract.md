# Evidence-owner routing contract

## Selection and identity

Name the question. Before you select one primary owner, reuse adequate fresh evidence. Preference never justifies retrieving an answered fact again. Treat "not configured" and "not applicable" as normal ineligibility, not as failures to repair. CodeGraph may be present without Serena, and Serena without CodeGraph. Boost is present only in applicable Laravel projects. Any combination of these providers, one alone, or none is valid. Select lazily from the eligible operations, and skip an absent provider without setting it up. Reuse capability evidence that is still valid, and verify only the capability you need. Do not run blanket health probes. Check the installed operation and its transport, the backend's coverage of the language, authority, freshness and target identity. Wherever relevant, identity includes the Git root, worktree and branch, the graph root, the Serena active project, and the intended application, environment and database. Reject evidence from the wrong root or the wrong environment for the local claim.

When the scope, branch, service or configuration changes, or the work resumes, check which evidence and capability state remains valid. Invalidate the affected entries instead of restarting discovery that is already covered. Parallel retrieval is allowed only for independently named questions when neither result can change the other's owner, scope, authority or query.

Before selecting Serena, check `.serena` at the resolved project root in the target worktree, not an arbitrary shell directory. By this pack's policy, a confirmed absence of that directory means Serena is not installed or configured for that project. Serena is then inactive for routing, whatever host binary or MCP endpoint is exposed. Skip Serena calls, activation and onboarding, and use eligible CodeGraph, native or Boost operations. Create no marker or integration without explicit setup scope. A directory status that cannot be read is unknown, not absent. The presence of the directory permits eligibility checks. It proves neither a connection, nor operation support, nor the active-project identity. A copied marker cannot retarget an inherited HTTP binding; verify that binding separately.

Never use CodeGraph MCP or CLI for a Bash or shell question, because CodeGraph does not support these languages (language evidence: `references/90-source-map.md`). This includes discovery, source reads, relationships and impact for scripts, extensionless shell files and embedded shell commands, even in indexed mixed-language repositories. Use bounded native search and read operations and the applicable shell tooling. /alaa-bash-shell owns implementation and validation. Do not probe CodeGraph or retry through another graph operation for these questions. Separate questions about supported non-shell source retain their normal route.

Known identity alone does not select Serena. For an adequate source or structural answer, use eligible CodeGraph first, then eligible Serena, then bounded native evidence. Send required semantics beyond CodeGraph directly to the capable semantic owner. Do not make a futile graph-first call. Native dependency metadata and resolution, literals, unsupported artifacts, Boost and runtime facts, and native proof keep the specialized owners in the table. The CodeGraph server and installer own exact usage and the managed instructions. Stack owners retain implementation doctrine. /alaa-repo-docs owns Markdown authoring and alignment, /alaa-workflow owns durable state, /alaa-low-noise owns output budgets, and the installed orchestrator owns fan-out.

Serena and its hooks are not prerequisites for native language operations. Record a known absence once for each unchanged capability context. Use an eligible CLI operation or connected LSP operation without a failed Serena call first. The stack reference owns operation fit. The native reference owns whether an executable or a client is eligible.

## Consume evidence

Reuse adequate fresh verbatim source, graph paths, metadata and prior results. Do not reread for reassurance. If a region is missing or stale, retrieve only that live region. A new semantic, implementation or runtime question must name its missing fact rather than repeat an answered one.

Honor returned provenance: heuristic edges, runtime dispatch boundaries and unexplained path gaps cannot establish a complete call path. Answer a missing dispatch fact through its eligible owner without restarting discovery. A text-search miss does not establish unused code.

Empty, unsupported, stale, paginated or truncated results do not prove absence or completeness. Complete only the needed bounded continuation pages or uncovered regions. If coverage cannot be established, keep the result marked unknown or partial. Do not turn pagination into a second reassurance query.

## Finite degraded operation

For each unchanged question, retain the established evidence and every attempted pair of owner and operation. Before each transition, record the missing fact, the failed capability and its cause, the next eligible operation and the lost guarantee. Mark each attempt before its call. Skip a candidate known to be unavailable or unsupported. Never cycle.

For a failed operation, allow at most one cause-specific, non-mutating repair of health or capability and one materially different retry, when the cause supports them. Otherwise, advance immediately. Activation, restart, unlock, sync or reindex are not automatic non-mutating repairs. A fallback uses a different eligible operation and never resets a failed operation's budget. Missing coverage alone is not a health failure.

- CodeGraph MCP transport failure: try the CLI only when it is independently usable against the same valid index. A shared stale or bad index skips this detour. Then use supported Serena or backend evidence, then bounded native evidence. Record the graph coverage that was lost.
- Missing required semantic operation: use an eligible language-native CLI operation or connected LSP operation that covers the same property, then targeted source for a partial read claim. Diagnostics alone do not establish complete references. Text does not establish refactor safety.
- Missing docs: use version-correct official sources after establishing installed versions.
- Missing native read or parser: use an available equivalent for the actual format and dialect. State the lost parsing or search coverage.
- Missing Laravel runtime capability: apply the independent failure domains for docs, application boot and database that the stack owner defines.
- Missing proof capability: use an authorized equivalent only if it proves the same property. Otherwise, report the exact gate blocked.

At exhaustion, give a partial answer or stop the dependent claim. Unrelated safe work may continue. A changed question or environment invalidates only the affected state, and never justifies repeating valid covered facts.

## Authorized native continuation

Authorized bounded local edits need no configured Serena, gopls or other semantic provider. When provider evidence is missing:

1. Name the behavior and the scope.
2. Use adequate fresh source or returned evidence.
3. Inspect the applicable contracts, callers and tests.
4. Verify the target worktree.
5. Preserve unrelated changes.
6. Inspect the resulting diff.

Run every mandatory native gate under the proof policy of the stack, the repository and the task. Source reads alone prove neither complete references, nor a binding-safe rename, nor refactor safety. If a required semantic property of the dependent action or claim lacks authorized equivalent proof, block only that action or claim. Sufficient evidence and the required proof permit the bounded edit without installation.

Provider diagnostics are supplemental unless repository rules or acceptance require a specific semantic property beyond native proof. Missing optional diagnostics do not block authorized edits or completion after the mandatory native gates pass. Record the gap and the lost guarantee. Do not claim that native output is equivalent without evidence. A required property that stays uncovered remains blocked; run the native gates for unrelated safe work.

## Mutation uncertainty

Before a semantic mutation, verify the task authorization, the supported operation and the target identity. After it, inspect the resulting diff and state. A timeout or uncertain result after a possible mutation requires reconciliation of the actual state before you continue. Never replay the mutation or automatically substitute text editing. If a safe resulting state cannot be established, stop that operation and report the unknown outcome. Fallback expands no authority.

For a failed native gate, permit one cause-specific repair and one retry within task authority. Otherwise, report the exact failure. No static or provider answer substitutes for an unrun gate.

## Handoff

Carry the established evidence, covered scope, worktree and environment identity, freshness, proof state, attempted operations and unresolved facts. The recipient reuses valid evidence and retrieves only the remaining gaps.
