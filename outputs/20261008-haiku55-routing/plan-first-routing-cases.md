# Plan-first routing acceptance cases

These are specification/review cases, not live model trials or proof of model obedience. The independent instruction review must inspect the shipped selection contract against each case; native gates separately prove registered pins, grants and generated output. No case requires replaying completed implementation.

| Case | Observable input | Required decision |
|---|---|---|
| C0 | Exact mechanical transformation across a finite enumerated existing-file set, settled design, known pattern, explicit exclusions and cheap discriminating checks | Permit direct automatic Haiku medium; many files alone do not reject it and no human model opt-in is required |
| C1 | Bounded settled engineering that still needs semantic implementation judgment, with clear focused checks | Select Sonnet medium directly |
| C2 | Harder or longer implementation with settled design and substantial local edge-case work | Select Sonnet high directly; no prerequisite C1 trial |
| C3 | Moderate unresolved engineering trade-off with bounded interactions | Select Opus medium directly; no prerequisite Sonnet trial |
| C4 | Interacting unresolved decisions, cross-boundary invariants and demanding consequence analysis | Select Opus high directly; complexity alone does not admit Fable |
| G1 | Same exact mechanical conditions as C0, possibly across many files, without an explicit Luna lane request | Permit direct automatic Luna medium; the plan records every fit predicate, and file count alone neither qualifies nor disqualifies |
| G2 | Ordinary engineering or moderate judgment appropriate to the current workhorse | Select Sol medium directly; no prerequisite lower-model trial |
| G3 | Substantial coupled reasoning, hard edge cases or interacting design choices | Select Sol high directly; difficulty alone does not admit Astra |
| G4 | Human requests Luna but a mechanical admission condition is missing | Human preference does not waive fit, authority or availability; return the mismatch to the lead |
| M1 | A superficially simple replacement has ambiguous matches, unspecified scope, public behavior to redesign or semantic choices between occurrences | Reject lightweight mechanical admission; retrieve facts or select the fitting workhorse, preserving required specialist gates |
| S1 | Predefined verification commands, bounded repository discovery or documentation are needed | Use the existing support role and its independent authority; implementation admission does not turn a verifier into a writer or grant external command permission |
| P1 | Planning scope, contracts and constraints are clear | Opus medium or Sol medium planner/profile |
| P2 | Planning must resolve interacting engineering uncertainties | Opus high or Sol high planner/profile; not Fable/Astra by complexity alone |
| P3 | High planner resolves design so implementation becomes bounded and settled | Select cheaper fitting implementation per lane; do not inherit planner cost automatically |
| P4 | Missing repository facts or product intent prevent a grounded plan | Retrieve/clarify through the owner; stronger models do not replace facts |
| E1 | Applicable recorded Opus-high/Sol-high inability on the remaining decision; context/spec/tools resolved; decomposition considered | Permit Fable/Astra with the evidence pointer and consequence; do not repeat a valid prior run |
| E2 | User explicitly selects Fable/Astra for this lane | Permit that profile without manufacturing a failed workhorse trial; availability and authority still apply |
| E3 | Large/sensitive project, many files, repeated generic failures or predicted workhorse weakness without E1/E2 | Reject strongest-model admission; choose fitting ordinary profile from plan |
| E4 | Failure is environmental, missing-context, ambiguous-specification or an ordinary fixable defect | Route the actual cause; no automatic model escalation by failure count |
| E5 | User merely mentions a model or asks to add support, without selecting it for the lane | Do not treat the mention as explicit strongest-model selection |
| R1 | Caller effort conflicts with a pinned Codex wrapper, or Claude per-call effort is assumed without support | Select the registered actual pair; do not claim ignored arguments changed the runtime |
| R2 | Required profile unavailable or overridden by incompatible effective controls | Report the selection/activation limitation; no silent substitution |
| R3 | Scope materially changes or a fix follow-up changes remaining judgment | Reassess at that boundary, preserve surviving work, retire old assignment and use one writer |

The Phase6 matrix had 20 approved cases. Phase7 supersedes its explicit Luna opt-in restriction following the user's request: C0/G1 allow automatic exact mechanical work, C1 distinguishes remaining engineering judgment, and G4/M1/S1 preserve rejection and role-authority boundaries. The current 23 cases are static specification/review evidence. Native gates validate exact role IDs against the canonical policies; this record does not become a second model-policy owner.
