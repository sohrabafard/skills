# All-role acceptance inventory

These are source and control-contract acceptance cases, not live model comparisons. Baseline inventories 34 Codex and 30 Claude controlled definitions, including each separately owned rule-writer. The independent reviewer must inspect actual final sources and identify any missing or contradictory case.

| ID | Required behavior | Evidence required |
|---|---|---|
| A1 | Every registered logical role has task-selected model and effort | Complete inventory versus policy, definitions and projections; no role family exemption |
| A2 | Bounded adversarial review can use an admitted workhorse pair | No automatic Fable/Astra pin; scope-based allocation example and control realization |
| A3 | Routine and demanding architecture review can select different pairs | Same authority contract, distinct task evidence; no role-only escalation |
| A4 | Instruction, security and deep-review titles do not imply frontier models | Active routing/projection evidence; same-model independence remains valid |
| A5 | Research, verifier, documenter, planner and rule-writer also select explicitly | Complete coverage and missing-control rejection, not implementation-only tests |
| A6 | Balanced remains the default, with justified task priority changes | Recorded task reasoning, unresolved decisions, acceptance, chosen pair and reason |
| A7 | Model changes preserve role authority and grants | Compare tools/denies/sandbox/skills/verdict duties against baseline; explain any intentional difference |
| A8 | Codex model-neutral files permit explicit spawn controls | No hidden pins in generated or authored definitions; native precedence accurately documented |
| A9 | Claude uses supported invocation model and non-fork effort | Current version/control gate; effective environment/hook/provider overrides inspected |
| A10 | Missing or partial controls cannot become implicit inheritance | Discriminating validation fixtures and dispatch stop contract |
| A11 | Stale installed pins or conflicting effective controls cannot be called successful selection | Configured/requested/resolved/observed distinction; mismatch evidence |
| A12 | Unsupported host/pair affects only that lane | Exact available realization or explicit blocked lane; no silent fallback/config mutation |
| A13 | Frontier escalation needs actual task evidence | No title, sensitive label, length, second lens or generic failure count shortcut; no mandatory trial ladder |
| A14 | Prompting knowledge, orchestrator judgment and workflow record ownership agree | Root/pack clauses, skill routers, allocation refs and templates contain no old fixed-role exception |
| A15 | Generated artifacts and consumers agree after migration | Affected policy/projection/grant/contract/eval gates and meaningful changed checker fixtures |
| A16 | Historical plans remain readable; new allocation evidence is honest | Workflow generator/validator regressions for model-only draft versus complete task selection |

No static PASS proves live account access, effective runtime isolation, serving identity, comparative quality or cost savings. Preserve those limits in the final report.
