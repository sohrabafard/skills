# Policy lane design

The ratified policy deltas are enumerated in intended-policy-deltas.json; policy-draft preserves the new intended contract before wording compression. Schema/policy versions, source verification dates and effort history remain unchanged. Eligibility is local task policy, not a new vendor capability claim.

Protected invariants: one allocation owner; explicit and exactly realized model AND effort; neutral authority identities; independent review/verification; focused implementation checks; fail-closed ordinary eligibility; preserved history; declared scope and side-effect limits; bounded failure/reassignment semantics.

Decision: separate support from eligibility using the existing boolean; use existing implementer-low authority for bounded non-bug Codex work and evaluate the task-selected cheap pair for every authority role. Preserve Luna-named mechanical/bug workload identities. Missing facts return to retrieval; unresolved cross-boundary judgment fails bounded admission.

Rejected: renaming old models in history loses dated evidence; new role/default pins would confuse authority with selection; widening Luna-named identities would require assets/catalog/generated changes; quotas and trial ladders violate ratification; moving text to mandatory references hides costs and changes loading. No relocation is needed.

Concurrency/partial failure: source scopes are disjoint from checker and parent writes. Final prose-sensitive checks wait for checker coordination. Preserve valid edits and separately report failed/unrun/blocked proof; do not repair other lanes. No runtime effects, data writes, installation or external actions are introduced.

Compatibility/rollback: existing JSON schema and role IDs remain; ordinary legacy selection deliberately rejects, with historical-only validation isolated by the checker owner. Source reversion is possible from the recorded before snapshot; it is no authority to change an installed or loaded session.
