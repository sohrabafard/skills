# Store Adapter: Hindsight

This adapter owns Hindsight query and write mechanics. `SKILL.md` owns recall admission, capability
classification, deadlines, authorization, shared-bank/project policy and drift; policy references own
knowledge shape. Use only the selected repository bank and service scope resolved from current approved
configuration. Activation does not authorize a new bank, broader scope or setup change.

When setup, configuration, ingestion, import, doctor/deepen recovery or self-hosted operation is in scope,
read `references/hindsight-setup.md`; routine recall and curated writes do not need its dated setup details.

## Upstream skill routing

After the body admits the work, invoke at most one upstream mechanics owner:

- /hindsight-docs for current architecture, API, SDK, deployment, configuration, debugging or best practices;
  read only the question's references. It selects no Alaa retained content.
- /hindsight-architect for a requested application integration design/review; it produces a plan, not code.
  Route accepted execution to /alaa-workflow and verify repository/security assumptions.
- /hindsight-upgrade only for an explicit installed-copy update request with authority for its effects.
  Never edit `vendor/hindsight-skills`; the repository vendor workflow owns that subtree.

If an upstream owner is unavailable, report the mechanics gap. The body's fail-open recall and fail-closed
write/drift rules determine what can continue; absence grants no installation or fallback adapter.

## Query mechanics

Use official MCP tools exposed by the selected harness. Ordinary recall uses bounded recall/reflect for the
current repository scope. An existence or ownership inquiry uses `hindsight_reflect` over raw memories,
with the capability/environment/constraint packet required by `SKILL.md`; page listing/search is not a
replacement because it reaches only topics that already have pages. Pass the same deadline to any one
focused owner-lead follow-up. Tool discovery, page hits and reflection results are leads, not current source
or exact-gate proof.

## Curated write mechanics

Use official retain/document-ingest tools only after body authorization and knowledge-shape admission.
Success requires Hindsight terminal completion; an accepted or queued request is not completion. An unknown outcome is not successful persistence; reconcile it through supported official mechanics
before repeating a possibly completed write.
Report the exact terminal or unknown outcome and preserve unwritten admitted content through the workflow
owner. Never substitute session retention or conversation import for a curated write.

When source language or extraction quality is in question, read `references/knowledge-shape.md`. Verify
current API/worker and bank/strategy settings against source-linked facts before claiming language
compliance; candidate language policy does not configure server extraction. A Reflect response uses the
question's language. Assess page prose quality separately from fact accuracy; mixed-source pages need not
have one language throughout.
