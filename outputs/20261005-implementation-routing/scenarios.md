# Implementation role-selection scenarios

For each case, apply the candidate orchestrator instructions. Return the role or pre-dispatch action for both runtimes, the evidence used, and the handling of any existing writer. Do not implement, dispatch, install or change files. These are independent cases; every fact needed for the decision is supplied below.

1. A service's reviewed migration plan specifies the exact new nullable column, a backward-compatible deployment order, and rollback. The remaining task is to edit the named migration and fixtures exactly as specified. Which implementation role receives it?
2. An authorization vulnerability has a reviewed fix: replace one untrusted-header read with the existing verified-context accessor and update its direct regression assertion. The contract and affected paths are settled. The security reviewer labels the finding critical. Route the fix.
3. Two worker processes may acknowledge a payment job before its write is durable. The observed interleaving is supplied. Product semantics are settled, but the implementer must choose between competing transaction/acknowledgement designs whose crash windows differ. No current design resolves that choice. Select the role and state its dispatch reason.
4. An existing difficult-role agent finished the design and implementation of a cancellation protocol. Review now requests only two specified message changes and one fixture value update; no lifecycle decision remains open. The agent is idle and has extensive context. Assign the follow-up.
5. During an active difficult-role assignment, the same documented crash-ordering decision remains open. A progress update adds a trace that narrows the choice without changing scope. Decide whether this update requires replacing the writer.
6. A test command failed twice because Docker access was denied. The command has not exercised the product. The implementer suggests upgrading its model. Route the next action.
7. A skill's exact replacement paragraph was approved, including its scope and exceptions. The task is to apply it to the two runtime projections and regenerate the existing manifest. Choose the implementer.
8. A user requests a new agent rule governing concurrent edits. Ownership handoff, interrupted-writer behavior and reconciliation are unspecified engineering mechanisms. Candidate rules differ on whether concurrent writers can overwrite each other. The lane must decide those mechanisms before writing the rule. Choose the role and identify the open decision.
9. A task uses the hardened pipeline because it includes an authorized production migration. A separate implementation lane must update an already-approved documentation link. Select this lane's role and explain whether the pipeline profile changes.
10. A request asks to choose whether failed payment attempts should be retried or discarded. No business policy states which outcome is acceptable. The task is labelled complex. Decide the next action and whether an implementation model can resolve the missing decision.
