# First full authoring draft

This is pass one under the prompting guide. It is authoring evidence, not an installed routing contract or live evaluation. The approved plan deliberately changes the one-secondary-owner cap and relocates detailed rules from the body. Compression must retain every decision below; rule relocation receives a separate migration review.

## Body and metadata draft

The skill acts as the evidence routing owner for CodeGraph, Serena, Laravel Boost and useful native tools. It applies when an agent must select a surface for discovery, exact semantics, semantic edits, framework documentation, runtime observation, native artifacts, review or proof, and when grants must be scoped. It does not implement domain code, own documentation authoring or workflow state, or itself prove completion. Activating this routing skill performs no setup or installation.

For every independently answerable question, name the fact needed and identify its target worktree and intended environment. Read the topic map and load only the reference matching the decision. The routing contract decides the primary owner, reuse and degraded operation. Ask the smallest bounded question and consume its evidence. Editing, observation and proof are distinct questions. Finish with required native checks. The metadata default prompt requests this same operation, not the old single-secondary-owner cap.

Routing grants no extra authority. Integrations, MCP, hooks, indexing, installations and configuration are changed only under an explicit request for their setup, upgrade, repair or removal. A fallback never makes a write safe or grants execution. Success requires questions answered, artifacts aligned and mandatory native gates observed to pass. Partial answers retain lost guarantees. If a missing fact, identity mismatch, unsupported safe operation, unauthorized effect or failed mandatory gate prevents a dependent step, stop that step and report its blocker; independent safe work may continue.

## Routing contract draft

One named question has one primary owner. Name the question before calling a tool. Verify only the capability needed by that question, lazily; do not probe every provider at startup. Identity includes Git root, branch/worktree state, graph root, active Serena project/backend, application/environment/database and command working directory wherever relevant. Wrong-root or wrong-environment evidence cannot establish a local claim. Scope, branch, resume, configuration or service changes invalidate only evidence and capability state they actually affect, but resumed old evidence needs its identity and freshness checked.

Unknown-location structural source discovery uses CodeGraph's installed exploration surface for supported indexed code. The server and installer own its exact invocation and managed instructions. Structural priority does not supersede known-symbol semantics, native artifacts, runtime observation or proof. Adequate fresh verbatim source returned with graph paths already answers a source question; do not fetch it again. Read only an omitted or stale region of a live file. Graph edge provenance constrains the answer: heuristic edges, runtime dispatch boundaries and unexplained gaps do not establish a complete path. A missing dispatch fact may have a targeted semantic, documentation or runtime owner; do not restart covered discovery. A text-search miss does not prove a symbol unused.

Known-symbol declaration, references, implementations, hierarchy and diagnostics use Serena only if the active backend exposes that operation. A stack-declared native semantic interface may replace it; for Go the approved route retains Serena and direct gopls only for a recorded missing supported operation. Text reads do not recover complete reference coverage or semantic refactor safety.

Known text/configuration/Markdown uses native bounded search, read or parsing. Do not start a graph or language server for a literal question. JSON/YAML/TOML parsing uses the actual dialect and proves syntax or selected source value, not effective runtime state. Generated artifacts are read through their source template and generator. Diff review begins from Git diff and names each unresolved risk. Documentation, implementation, workflow, fan-out and output policies remain with their existing skills.

Installed-version Laravel guidance uses Boost docs first after versions are established. Installed source can answer a newly named implementation question; it does not replace framework conventions. Registered routes, application information, URLs, schema, errors, logs and DB queries use an appropriate available Boost operation or equivalent authorized native observation. A URL is not proof of route registration. Static source routes and migrations describe intent, not live state. Tests, types, lint, build, formatting and generated/link checks use inspected native recipes; discovery output never substitutes for proof.

For each unchanged question preserve established evidence and a set of attempted owner/operation pairs. On failure record the missing fact, failed capability and cause, next eligible operation and lost guarantee. Skip candidates known unavailable or unsupported. For a cause that supports it allow at most one non-mutating health/capability repair and one materially different retry of that failed operation. Do not silently activate, restart or reindex as health repair; if mutation is required it needs separate authorization. Empty and truncated results are coverage limitations, not availability failures by themselves. Follow bounded continuation pages or retrieve the exact missing region when required, without repeating covered facts. When full coverage cannot be established, retain partial or unknown rather than absence.

Fallback is finite: CodeGraph MCP transport failure can reach CLI against the same independently valid index; shared stale/bad index failure skips that transport detour. Then a supported Serena/backend operation may answer the gap, then scoped native evidence can supply a narrower read claim. Known semantics may use a configured equivalent native semantic operation, then partial targeted reads. Documentation may use version-correct official sources. Native read/parser operations may use an equivalent available native operation and retain any lost parser guarantee. Runtime observation needs the same intended application/environment/database. Native proof may use an authorized equivalent recipe only if it proves the same acceptance property; otherwise it is blocked. Mark attempts before calls, never cycle, and never reset attempts merely because the owner changed. Exhaustion stops the dependent claim while unrelated safe work continues.

Semantic writes require task authorization, correct project, supported operation and diff inspection. A timeout after possible write requires actual state reconciliation before any continuation. Do not replay the mutation or substitute text editing automatically. If the resulting state cannot be determined safely, stop the operation and return the unknown outcome. Parallel retrieval is allowed only for named independent questions when neither result changes the other's query, owner, scope or authority. Handoffs include covered evidence, identity, freshness, proof and unresolved gaps; recipients reuse valid evidence.

## Stack and capability draft

Boost docs transport, application boot and database health are independent. A docs outage retains healthy application metadata and uses official version-correct docs. A boot outage retains documentation and direct installed package metadata; another Artisan command sharing boot is not independent recovery. A DB outage retains docs/application evidence; equivalent DB observation must reach the intended connection and environment, or live schema is blocked. Unknown package installation requires direct installed metadata, with lockfile intent identified separately. Logs need application identity, window and freshness, are sensitive, and no logs do not prove no failure.

Capabilities are conditional on inventory, version, backend, context, language coverage and permission. CodeGraph's explore combines source, paths and impact; narrower node/query/files/callers/callees/impact/context commands are used only when present and needed for a gap. Affected-test suggestions do not execute tests. Status/version are health evidence; index/sync/unlock/init/uninit, daemon control, installer/removal/upgrade and telemetry changes are lifecycle effects, never automatic fallbacks. An unreleased viewer is excluded rather than installed.

Serena symbol operations, optional symbol diagnostics, backend-specific hierarchy/inspections and specialized rename/move/inline/safe-delete operations require their exact supported backend. File/search tools add no semantic guarantee. Shell execution, REPL/debug evaluation and arbitrary expressions have execution authority even if a requested expression looks read-only. Optional/beta REPL cannot be treated as a constrained read grant without enforcement evidence. Current configuration and manual instructions can establish inventory; activation/onboarding/restart/config removal have effects. External-project queries require explicitly named repository authority and identity. Provider memories remain outside this routing skill's memory ownership. A supplied tool does not authorize its use.

Boost's application info, documentation, connection/schema/query, URL/routes, logs/errors, installed command inventory/execution, tinker-style execution and rule recording are separately classified when installed. A SQL query tool is not proof of a read-only credential or harmless query. Commands and arbitrary code can mutate; rule recording writes durable agent instructions. Generated guidelines/skills and install/update are setup effects. No one blanket grant covers these operations.

## Native guide draft

Bundle useful native guidance, not a host catalogue. Check only the selected executable with Get-Command or command -v, project configuration and version/dialect. Never auto-install or allow package-runner downloads. Inspect repository scripts/Makefile/manifests/config before executing a recipe; labels like check or dry-run do not prove no side effects. Bound input/output and exclude secret payloads.

Files/literals use rg and known-file reads; fd can find paths if installed; native shell equivalents retain ignore and hidden-file limitations. ast-grep supplies supported syntax matching, not binding/type resolution. jq/yq or an installed language parser handles structured data in the correct dialect. Git status/diff/show and root/branch checks prove saved working state, not service identity. PHP/Composer and configured Pest/PHPUnit/PHPStan/Pint use project recipes; formatter fix modes write. Artisan boots the application and may reach dependencies. Go toolchain, configured tests/vet/build/formatter/linter wrappers, gotestsum and direct gopls are selected for specific gaps; tests may run subprocesses/dependencies. Package-manager scripts use lockfile-selected installed tooling and stack owners. Missing proof tools stay blocked unless an approved equivalent proves the same property.

## Binding and grants draft

Replace nonexistent setup-tree dependencies with a portable binding fragment and Serena initial-prompt fragment inside reference 70. Preserve repository-specific enabled-surface declarations and proof commands as named placeholders; never invent them. For Laravel the official custom-guidelines directory is an editable source for generated instructions; inspect the installed generator's ownership before deciding where to write. Preserve outside content and do not hand-edit generated sections or create parallel canonical copies. Non-Laravel repositories use their authoritative instruction owner without imposing a cross-runtime import. Serena context follows the actual MCP client and effective inventory. Generated schema, one generated language-selection key, recurring semantic needs, health and resource cost decide backends; do not add languages for file coverage. Setup changes remain authorized separately.

Reference 80 owns grant restrictions. Read-only roles receive exact observed read tools only, never full-server access. MCP writes/execution are outside native sandbox guarantees. Optional/backend read tools must have verified read semantics before inclusion; unknown operations are denied, not guessed harmless. Pure command verifier roles get no provider grant. Boost grants are separate by needed question. The orchestrator owns role assignment and prompting guide owns runtime syntax. Observe resolved grants, launch behavior and contract reachability; parse alone is insufficient. Do not widen tools through dispatch prose.

## Evaluation and provenance draft

Evaluation distinguishes static checks, declared outage scenarios, observed runtime behavior and measured performance. Define expected decisions for S01-S15 before trials. Use disposable fixtures or declared unavailability, never mutate service/MCP registrations to simulate an outage. Record runtime/version, requested and observed model/effort, worktree, capability assumptions, question, operations, reuse/duplicate counts if observable, lost guarantee, termination and actual native results. Unavailable runtime cells remain unverified and native gates do not prove instruction compliance. Comparable baseline/environment is required before a speed claim. The source map records refreshed official links/date and discrepancies, with local observations kept distinct from upstream potential capability. The separate capability ledger maps every included or excluded group to trigger, operation/transport/backend, authority, source/date/version, limit, fallback, owning rule and scenario.

Preserve managed installer entries, project-local activation/cleanup, reminder-profile conflict evidence, opt-in hooks, no authority broadening and rollback of introduced entries only. No integration configuration is changed by this task. Preserve all source caveats and native proof requirements. Compression removes repeated narration only; relocation and approved behavioral changes are separately recorded.
