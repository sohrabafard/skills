# Compression evidence

## Draft contract

Implementation roles execute only commands supplied by the dispatch or established by repository guidance whose actual scope is focused: the lane's failure-mode tests and lint, type and build checks limited to the touched files. A label saying focused does not make a command eligible. They never execute affected or exhaustive checks, including the full suite, race detector, end-to-end suite or another lane's checks. Those checks belong to independent gates, and duplicating them mixes authority and pays twice. If dispatch text requests forbidden breadth, report both the conflict and the commands excluded. Execute only already-known focused commands that are separable from excluded work. Do not execute an ambiguous command or an inseparable mixed command. Do not invent replacement commands or flags. If no eligible command exists, report validation not run and request focused commands from the parent. Implementation evidence never discharges independent acceptance. Existing resource controls and failure routing remain binding.

Before dispatch, the lead classifies every command by actual scope, assigns focused commands only to implementation lanes, and reserves independent gates for their independent observer. Citation requires unchanged inputs and the correct independent observer. An implementer's broad PASS remains implementation evidence and cannot close independent acceptance. Valid unchanged independent results are cited with their provenance. Exhaustive verification remains fresh on the final candidate.

Gate-economics draft: retain cost classification and repository-policy precedence. Resolve cheap reviews and triggered specialist findings before an expensive verification dispatch, never concurrently, because a fix invalidates an ongoing expensive pass. When expensive, Phase D runs before Phase C without renaming phases or owners. Run the expensive gate once on the reviewed tree; a second dispatch of the same gate inside one phase indicates the ordering was skipped. Freeze it first: commit only with explicit permission on the work branch, otherwise pin authorized tracked/untracked/tool inputs and prevent concurrent writes. Content evidence does not require a commit. Workflow retains protocol ownership.
